此刻没有排期的计划。下面这些是外壳的窗格与桌面上想过、决定先不做的事：不是漏了，是有意留着。
哪一条要做，先把它后面写的那个问题想清楚，再在 `future/spec/` 下开一页方案。

## 窗格与桌面

- **独立窗口**：把一组弹成单独的操作系统窗口。VS Code、Obsidian 都有，dockview 也有弹出组
  （`addPopoutGroup`），但它牵扯多个窗口之间怎么协调——外壳眼下是「多窗口时各页各自执行」。
  手势约定里 Shift+单击（Chrome 与 Obsidian 里是新窗口）因此也先不分配含义
- **把标签一路拖进另一张桌面的某一组、指定位置**：拖到状态栏「桌面」面板里的桌面上就是送过去，按目标组规则
  决定位置，这已经有了。像同一张桌面里那样拖进目标桌面、选组选边，要让目标桌面的那个 dockview 实例接收从别的实例
  拖来的标签，dockview 没有现成的接口
- **快捷键**（切桌面、送到桌面、开到旁边）：可以参考 Windows 的 Win+Ctrl+←/→，但外壳的快捷键跟各插件自己的
  快捷键怎么划分，要先单独想清楚
- **「已开就跳过去」的设置**（VS Code 的 `workbench.editor.revealIfOpen`、macOS 切到应用所在空间的那个开关）：
  文档窗格固定为不跳，在目标组再开一份；真有人要再加
- **桌面排序**：桌面按新建的先后排，不能拖动调整顺序
- **新标签在后台打开**（Chrome 里 Ctrl+单击的缺省行为）：手势约定里 Ctrl+单击开的新标签一律激活
