## 现场

日志插件（`plugins/gwb-bn-journal`）照说明书 `gwb-shell`「写浮层」一节，把 shadcn 的 `PopoverContent` 加了 `container`、挂到 `args.shell.portal`。
浮出卡能打开、样子正常，但卡里的按钮用鼠标点没有任何反应：点击穿过卡片，落到了下面窗格里的元素上。

原因：外壳给每张桌面的浮层挂载点写的是 `gwb-portal-host shell:pointer-events-none shell:absolute shell:inset-0`（`plugins/shell/src/client/index.tsx`），挂进去的内容继承 `pointer-events: none`。

- 模态的浮层不受影响：Radix 的 Dialog、AlertDialog、Select、默认模态的 DropdownMenu，会在内容上用内联样式写 `pointer-events: auto`（DismissableLayer 的 `disableOutsidePointerEvents`），所以单元文件夹插件的下拉菜单、日志插件的 Select 都能点
- 非模态的浮层都中招：Popover（默认非模态）、HoverCard、Tooltip 里带可点内容的、`modal={false}` 的 DropdownMenu

日志插件那边先在自己的 `components/ui/popover.tsx` 的 `PopoverContent` 类名里加了 `pointer-events-auto` 绕过去。

## 期望

二选一，由外壳定：

- **挂载点的直接子元素恢复指针事件**：比如外壳的样式里写 `.gwb-portal-host > * { pointer-events: auto }`，挂载点本身仍然不挡下面的窗格，插件不用各自处理
- **维持现状**：在说明书 `gwb-shell`「写浮层」一节写明，非模态浮层的 Content 要加 `<前缀>:pointer-events-auto`，并把它列进要改的那几处本地改动里

## 证据

隔离 home `bnj-shadcn-2609301609` 里装了日志插件的开发版（修之前的那一版），打开年月选择后用 `devkit.cdp` 的真实点击点卡里的「10月」按钮，回执：

```
"why": "这个点打不到目标，被别的东西接管了",
"blocker": "div.bnj:flex.bnj:min-h-0 … （卡片下面月历里的一格）",
"pointerEvents": "none"
```

加上 `pointer-events-auto` 之后同一次点击命中按钮，月历翻到了 10 月。jsdom 里的单元测试不算样式，这个问题测不出来，只有真实点击才看得到。
