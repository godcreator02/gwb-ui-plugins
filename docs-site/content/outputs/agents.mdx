## 这个仓是什么

**gwb 的 UI 平台仓**——2026-09-12 三仓拆分从 `gwb-base-plugins` 分出（方案页在旧仓 spec 区
`2026-09-12-three-repos-split`）。立场先立住：**shell 是一个 UI 平台的整体，要换整套换**；
tokens（视觉契约）与 shared-react（react 运行时口粮）跟 shell 同仓同进退，不为假想的第二
外壳实现维护独立契约包。

|      | 件 / 包                                                    |
| ---- | ---------------------------------------------------------- |
| 外壳 | `shell`（窗格井 + 窗格注册服务，内核页面根的唯一入口）        |
| 外观 | `theme`（全局启动样式 + 外观窗格；没外壳也照常挂）           |
| 基础界面 | `baseui`（基础件的官方窗格集：日志、插件管理）            |
| 共享包 | `shared-react`（react 系经内核 importmap）、`tokens`（令牌表） |

## 依赖纪律

- peer 一律 `>=` 不写 `^`（caret 在 0.0.x 锁死 patch）
- **跨仓基础件**（commands / data / settings / logger / plugin-manager / plugin-api）的
  dev 写 **registry 精确版本**——本仓没有它们，`workspace:*` 解析不到
- **同仓包**（shell / theme / baseui / shared-react / tokens 之间）dev 照旧 `workspace:*`
- 依赖流向单向：本仓 peer 基础仓，永不反向

## baseui 三规矩（哪条破了它就吸成上帝件）

1. 对每个 core 服务**一律嵌套注入**，硬 inject 只有 `gwbShell`——缺谁少画谁的窗格
2. **一窗格一模块**：`panes/` 下窗格之间零 import，只准 import `components/ui` 共享层
3. **只收「劈过件的皮」**：进 baseui 的唯一资格是它是某个 core 件的官方脸；UI 即本体的件
  （hello、将来的功能件）自带皮，不进

```bash

```

写件的整条路在 `gwb-devkit` 件的 skill。

## 门禁

提交前都要绿：`pnpm check`；文档检查单独 `cd docs-site && pnpm doc`。
