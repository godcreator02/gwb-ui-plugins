# 系统地图

**本页回答**：`gwb-ui-plugins` 拆成哪几个模块、各在哪、模块之间谁依赖谁、新来的人先读哪个。

## 模块

一行一个模块。「在哪」是包根（`dist/` 是生成物，`build.ts` 在各包根下打各自的产物）：

| 模块 | 在哪 | 管什么 | 先读 |
| --- | --- | --- | --- |
| 外壳 | `plugins/shell/src/` | 窗格注册服务（node 端）＋ 多个 dockview 窗格容器（well，代码模块 `well-hub`；浏览器端）——内核页面根的唯一入口 | [外壳](/docs/shell) |
| 外观 | `plugins/theme/src/` | 全局启动样式（字体＋自定义 CSS）＋「外观」窗格；没有外壳也照常加载 | [样式与组件](/docs/styles) |
| 基础界面 | `plugins/baseui/src/` | 基础插件的官方窗格集（日志、插件管理），一个插件多个窗格、浏览器端按 `pane.id` 分派 | [样式与组件](/docs/styles) |
| 令牌 | `plugins/shell/src/tokens/` | 语义变量亮暗两套＋preflight＋层顺序声明；没有 node 端代码，产物是外壳包里的两份 css（`theme.css`、`theme.reference.css`） | [令牌与颜色](/docs/tokens) |
| 共享 react | `plugins/shell/src/shared/` | react 四个包名的 CJS→ESM 打包产物，随外壳包发布，经页面 importmap 让全页共用同一份实例 | [样式与组件](/docs/styles) |

「一个 UI 平台的整体，要换整套换」——五个模块放在同一个仓、一起换的立场与判据在[样式与组件](/docs/styles)。

## 依赖方向

单向，四条箭头：**插件 → 令牌**（构建期引映射面、运行期读页面那份值）、**插件 → 外壳**（注册窗格时报两个地址；浏览器侧 `import type` 外壳子路径 `@godcreator/gwb-shell/pane` 的类型，见[外壳](/docs/shell)「类型从 `@godcreator/gwb-shell/pane` 引」一节）、**外壳 → 主题插件**（一条软契约命令）、**本仓 → 基础仓**（peer 基础插件，永不反向）。逐模块的「它不知道什么」那张表在[样式与组件](/docs/styles)第二节。

## 每块一页

每个模块在这一区有自己的一页，固定块按这个顺序：

管什么 / 不知道什么 / 数据结构（只钉形状，不列字段）/ 提供的接口 / 依赖的接口 / 怎么单独测 /
代码地图（在哪、先读、读序、可跳过）。

本仓的现状页按功能线组织、不按包分：[外壳](/docs/shell) 一页，[样式与组件](/docs/styles) 一页覆盖
theme / baseui / 令牌 / 共享 react 的契约与原理，[令牌与颜色](/docs/tokens) 是令牌规则的
正本，[撞过的墙](/docs/walls) 记录这个仓踩过的坑。
