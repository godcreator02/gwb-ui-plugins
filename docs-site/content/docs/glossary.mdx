## 插件与页面

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| cordis | 工作台主进程里加载插件的框架；插件的上下文、服务的提供与注入、插件卸载时的自动清理都来自它 | [首页](/docs) |
| 外壳 | 接管内核页面根、在上面画出窗格容器、桌面与状态栏的插件；一个页面只有一个外壳，后接管的替换先接管的 | [外壳](/docs/shell) |
| 页面根 | 内核窗口里交给外壳渲染的那个根元素；换外壳时内核先让旧外壳清理，再交给新外壳 | [外壳接管](/docs/shell/takeover) |
| 只读状态页 | 没有外壳、或外壳启动失败时内核自己在页面根里显示的一页：home、各条目的状态、最近的错误 | [外壳接管](/docs/shell/takeover) |
| node 侧 / 浏览器侧 | 一个插件的两部分：node 侧在主进程里由 cordis 加载，登记服务与命令；浏览器侧打包成一个脚本，在页面里画窗格 | [首页](/docs) |
| 条目 | home 的插件配置里的一条；同一个包可以配成几条，各自独立加载，窗格与插件名都按条目区分 | [窗格](/docs/shell/panes) |
| 必需依赖 / 局部注入 | 插件依赖别的插件提供的服务的两种写法：必需依赖缺了本插件不加载；局部注入只让一段代码等那个服务，缺了本插件照常加载、只少那一部分功能 | [首页](/docs) |
| 按命令名调用 | 不引对方的包、只经命令总线按名字调它的命令；命令不在时回执写明，调用方不需要把对方写进依赖 | [首页](/docs) |
| 转发类命令 | 动作要在页面上执行的外壳命令：node 侧校验参数后把动作推给页面，回执成功只代表转发了，不代表做完了 | [首页](/docs) |
| 基础插件 | 别的仓里提供命令总线、数据、设置、说明书、日志、插件管理这些服务的插件；它们不依赖本仓 | [首页](/docs) |

## 窗格

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| 窗格 | 插件在外壳里占的一块界面：插件登记的是窗格的定义，外壳按定义打开的每一份是一个实例 | [窗格](/docs/shell/panes) |
| 窗格注册表 / 插件名表 | 外壳 node 侧的两张表：前者按「条目 × 窗格」记每个窗格的定义，后者按条目记插件报给人看的名字 | [窗格](/docs/shell/panes) |
| 窗格契约 | 外壳与窗格插件浏览器侧之间的约定：外壳加载插件的脚本、调它导出的挂载函数并交出一个容器，插件同步交回一个清理句柄 | [窗格](/docs/shell/panes) |
| 工具窗格 / 文档窗格 | 注册时说明的两类窗格，区别在打开这个动作的含义：工具窗格整页至多一份，打开就是把它显示出来；文档窗格可以开多份，每份装一个内容 | [窗格](/docs/shell/panes) |
| 份 / key | 同一个窗格开出的一个实例叫一份；插件打开时给的 key 说明这一份装的是什么内容，外壳只拿它找已开的那份，不解释它 | [窗格](/docs/shell/panes) |
| 预览窗格 | 标题前带空心圆点的临时窗格：下一次以预览方式打开时原地换内容；人开始用它或插件要求留住时转成正式窗格，转了就不再被替换 | [窗格](/docs/shell/panes) |
| 软换 / 硬换 | 外壳换了一份窗格的内容之后怎么通知插件：插件的句柄带换内容的函数就调它（软换），不带就卸载后重新挂载（硬换） | [窗格](/docs/shell/panes) |
| 来源窗格 | 发起这次打开的那一份窗格；新窗格开在它那张桌面上，目标组以它为参照来算 | [窗格](/docs/shell/panes) |
| 组 / 侧边组 | 组是一排标签共用的那一块区域，分屏就是几组并排；侧边组是紧挨在某一组右边的那一组 | [窗格](/docs/shell/panes) |
| 最近用过的同类组 | 当前桌面上最近一次被激活、且装着同一个窗格定义的某一份的那一组；只在运行时记，整页重载后从空开始 | [窗格](/docs/shell/panes) |
| 目标组 | 这一次打开开进哪一组：按摆放方式、来源窗格与最近用过的同类组算出，要新建组时只把基准组对半分 | [窗格](/docs/shell/panes) |

## 桌面与布局

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| 桌面 | 一套独立的窗格摆放，同一时刻只显示一张；切走的桌面不卸载，窗格照常运行 | [桌面与布局](/docs/shell/desktops) |
| dockview | 外壳用来画窗格、标签与分屏的第三方布局库；打包在外壳的浏览器侧里，不用它自带的主题 | [桌面与布局](/docs/shell/desktops) |
| 窗格容器 | 装窗格的那个 dockview 实例，一张桌面一个，切走也不卸载。代码里叫 well | [桌面与布局](/docs/shell/desktops) |
| 浮层挂载点 | 每张桌面上给插件放下拉菜单、对话框这类浮层的元素；浮层放在这里，桌面切走时跟着一起隐藏 | [桌面与布局](/docs/shell/desktops) |
| 送到 / 拉到本桌 | 把一个窗格挪到别的桌面：源桌面关掉、目标桌面开一份正式的，插件的状态只靠参数带过去，当前显示的桌面不变；拉到本桌是送到当前桌面 | [桌面与布局](/docs/shell/desktops) |
| 布局文件 | 外壳存在数据插件里的一份文档：每张桌面的布局、重启回到哪张桌面、人起名存下的布局 | [桌面与布局](/docs/shell/desktops) |
| 已存布局 | 人在状态栏给当前桌面的布局起名存下的一份，应用到当前桌面后即弃，之后照常自动保存 | [桌面与布局](/docs/shell/desktops) |
| 布局没读回来 | 开机读不回布局文件、或某张桌面的布局恢复不了的状态：照样按默认布局打开，但停止保存，等人确认后才覆盖磁盘上的文件 | [桌面与布局](/docs/shell/desktops) |
| 状态栏 | 页面底部外壳自己画的一条，放桌面、新建窗格、布局、版本这些入口；它压在所有桌面之上，始终能点 | [状态栏](/docs/shell/statusbar) |
| 启动器 | 状态栏的「新建」菜单：每次点开当场读取注册表，按插件分组列出能打开的窗格 | [状态栏](/docs/shell/statusbar) |
| 「桌面」面板 | 状态栏里列出所有桌面与上面窗格的面板：点一张切过去，把窗格拖到另一张上就送过去 | [状态栏](/docs/shell/statusbar) |

## 样式与模块

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| 令牌 | 样式里引用的语义变量（背景、主色、边框、字体……），亮暗两套值；插件的样式只引用变量名，不写具体颜色 | [令牌](/docs/shell/tokens) |
| 全局令牌 | 跨插件共享的那一级令牌，全页只有一份，由外壳发布与注入；与之相对的一级是插件域令牌 | [令牌](/docs/shell/tokens) |
| 令牌表 / 映射文件 | 令牌的两个文件：令牌表放变量值、由外壳在页面上第一个注入；映射文件只告诉编译器类名怎么对到变量，插件在构建期引用，不输出任何值 | [令牌](/docs/shell/tokens) |
| 插件域令牌 | 只有某个插件自己用的颜色变量，名字带插件前缀，值与颜色类都在这个插件自己的包里 | [令牌](/docs/shell/tokens) |
| 层顺序 | CSS 级联层之间的先后声明。没放进任何层的规则压过所有分层的规则，所以层顺序由页面上第一张样式表（令牌表）统一声明 | [令牌](/docs/shell/tokens) |
| preflight | Tailwind 自带的一份全页基础样式重置；放在令牌表的基础层里，全页只有一份，插件的样式表不引它 | [令牌](/docs/shell/tokens) |
| 类名前缀隔离 | 每个插件的工具类名都带自己的前缀，样式规则全页有效但只匹配本插件画出的元素；隔离靠类名唯一，不靠元素在哪 | [样式](/docs/shell/styles) |
| 样式检查 | devkit 对带界面的插件产物做的检查：类名带前缀、颜色只用令牌、变量引用不写死默认值；没过的不装、不发 | [样式](/docs/shell/styles) |
| 启动样式 | 外观插件按字体与自定义 CSS 三项设置拼成的一段样式，外壳开机时写在所有样式表之后、第一帧之前 | [外观](/docs/theme) |
| 浏览器模块登记 | 插件把一组包名对应到自己产物里的文件、交给内核，页面上的代码按包名 import 时解析到这些文件 | [页面用的 React](/docs/shell/react-runtime) |
| 外置名单 | 构建浏览器侧时不打包、留给页面按包名解析的那几个包名，就是外壳登记的那几个 | [页面用的 React](/docs/shell/react-runtime) |
