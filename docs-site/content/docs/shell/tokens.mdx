令牌是全生态共用的视觉契约，随外壳包发布，分成两个文件：

| 文件 | 谁用、什么时候用 | 里面是什么 |
| --- | --- | --- |
| `@godcreator/gwb-shell/theme.css` | 外壳开机时第一个注入页面 | 层顺序声明、preflight、令牌的值（亮色 `:root`、暗色 `.dark`）、两条全页默认规则 |
| `@godcreator/gwb-shell/theme.reference.css` | 每个带界面的插件构建时引用 | 类名到令牌变量的映射，一个值都不输出 |

## 值与映射为什么是两个文件

插件以 `theme(reference)` 引用映射文件。这种引用只拦得住 `@theme` 块的输出，拦不住普通规则：

{/* ref file="../plugins/shell/src/tokens/theme.reference.css" lines="1-2" hash="c42f2e242752" blob="f5bcf4c3f472" */}

把写着 `:root { … }` 的变量值文件一起引进插件的构建，每个插件的产物里都会多出一整份 `:root`，跟页面上那份并存，
而且因为插件的表加载在后，插件构建那一刻的旧值会覆盖页面上的值（上面演示的最后一步）。拆开之后，映射让类名解析得出来，
值仍在运行时取页面上那一份。

映射之所以非有不可，还因为样式入口第一行带的前缀：`prefix(baseui)` 连 Tailwind 内置的主题变量名也一起改掉，
每个插件改出来的名字各不相同。在页面上全局声明一份 Tailwind 默认主题变量影响不到任何插件，语义令牌只能经映射文件传进去。

同一个道理，Tailwind 出厂的刻度（间距、字重、字距、白与黑、阴影、缓动、过渡、容器断点）也由映射文件接管、值写在令牌表里。
不接管的话，插件产物里会留下 `var(--baseui-spacing, 0.25rem)` 这种带字面默认值的引用；接管之后产物里没有字面默认值，
这些尺寸也能随主题换。值照抄 Tailwind 的出厂默认，观感不变：

{/* ref file="../plugins/shell/src/tokens/theme.reference.css" lines="55-77" hash="e68be57f7dd5" blob="f5bcf4c3f472" */}

映射键名以 Tailwind 某个版本的出厂 `theme.css` 为准，升 Tailwind 大版本时先照文件头那行核一遍键名。
为什么把出厂刻度收进令牌表，见[令牌国有化](/trajectory/2026-09-12-token-nationalization)。

## 层顺序与 preflight 为什么由令牌表管

`theme.css` 不经 Tailwind 编译，由外壳的 `build.ts` 拼成：先声明层顺序，再把 preflight 包进 `base` 层，最后接上令牌的值：

{/* ref file="../plugins/shell/build.ts" lines="140-154" hash="2363be344e33" blob="4dc419913506" */}

插件的表只写 `@layer utilities`、不声明层与层的先后，所以顺序只能由先加载的那张来声明，令牌表就得是页面上第一张。
preflight 原样放进去是一份不在任何层里的规则，而 CSS 里**不分层的规则优先级高于所有分层的规则**，它会覆盖每一个插件的工具类，
所以必须包进 `base` 层。同一条语法事实的另一面是：外观插件注入的用户自定义 CSS 不分层，所以它能覆盖令牌的默认值和任何插件的工具类
（见[外观插件](/docs/theme)）。

令牌表末尾还有两条全页只该有一份的规则：给所有元素一个默认边框色，给 `body` 定底色、文字色与字体。
不经 Tailwind 工具类的 DOM（dockview 画的标签条、插件里没写类的普通元素）全靠从 `body` 继承字体：

{/* ref file="../plugins/shell/src/tokens/tokens.css" lines="98-111" hash="82e9d70b2db6" blob="ce74d1a59f41" */}

整个工作台一种字体（更纱黑体等宽），正文与等宽仍是两个变量 `--gwb-font-sans` / `--gwb-font-mono`：插件写 `font-mono` 表达的是
「这里是代码」，外观插件的字体设置覆盖的也是这两个名字。

## 两级：全局令牌与插件域令牌

判据只有一条：这批样式要不要跨插件一致、要不要跟着工作台的主题走。

| | 全局令牌 | 插件域令牌 |
| --- | --- | --- |
| 管什么 | 跨插件共享的语义：背景、前景、主色、卡片、边框、muted、状态色 | 插件自己产品里的视觉词汇，如编辑器的高亮色盘、日志来源圆点的颜色 |
| 写在哪 | 外壳包的令牌表，全页只有一份，由外壳注入 | 插件自己的包里，随插件的样式表一起进页面 |
| 跟主题 | 换值后所有插件一起变 | 默认不跟；派生自全局令牌的那部分自动跟着变 |

「全页只有一份」只说全局令牌这一级。把插件域的颜色也塞进令牌表，跨插件共享的名字就混进了只有一个插件在用的东西。

拿到一个新的样式值，从成本最低的问起，问到哪一级就停在哪一级：

| 问 | 停在哪 | 例子 |
| --- | --- | --- |
| 只用一次的装饰？ | 任意值写死（`bg-[oklch(…)]`，或插件里一段普通 CSS） | 一处小点缀 |
| 本插件里多处用、只有本插件有这个视觉概念？ | 插件域令牌 | 日志来源圆点的颜色 |
| 跨插件要一致、主题要管？ | 全局令牌 | 警告色、间距基数、阴影刻度 |

插件域令牌在第二个插件也要用它的那天升成全局令牌。

## 颜色分级

拿到一个新颜色，先问：换主题时它该不该变？

| 判据 | 性质 | 做法 |
| --- | --- | --- |
| 该变，而且跨插件要有同一个含义（警告、危险、品牌） | 语义色 | 升成全局令牌：`tokens.css` 加亮暗两套值、`theme.reference.css` 加映射，外壳发版；插件升依赖、重新构建后写语义类 |
| 该变，但眼下只有本插件在用 | 先用已有的语义色 | 这种颜色多半就是 accent、muted、destructive 的别名；确实没有对应的再考虑加令牌 |
| 不该变（纯装饰，明确不跟主题） | 装饰色 | 明确写死：任意值或插件里一段普通 CSS，要答得出它为什么不跟主题 |

三条不许：

1. **不许用 Tailwind 内置调色板的类表达语义色**：调色板查的是 Tailwind 出厂的颜色表，不查令牌，换主题不跟着变，也不报错
2. **不许把语义色写成字面值**（hex、oklch）：理由同上
3. **不许插件自带一套私有令牌包**：插件自己的「映射文件加变量值文件」等于再造一张令牌表，值进不了页面上唯一那一份，换主题换不到它；
   要让外壳注入它就得改外壳，又回到集中登记。全生态只有一张令牌表，特殊颜色只有上表那两种写法

## 令牌怎么演进

令牌的名字清单是全生态的公共契约：

1. **改值随便**：那是主题的本职。改 `tokens.css` 里的值、外壳发版、home 升级，所有插件不用重新构建就当场变
2. **加名字随便**：向后兼容。不用新令牌的插件什么都不用做，用它的插件升依赖、重新构建
3. **不许删名字**：删掉一个，所有还写着那条 `var()` 的插件当场读到空值，而且不报错。名字一旦发出去，只能标成废弃、继续保留

## 插件域令牌怎么写

值与注册分两处，都在插件自己的包里。以 baseui 日志的来源圆点为例，值写在 `src/client/tokens.css`：名字带插件前缀，
不跟全局令牌重名；写在 `:root` 上，portal 到窗格外面的浮层也读得到：

键名被前缀改写也不影响，产物里没有字面默认值：

插件域变量优先派生自全局令牌（`var(--accent)` 这种），只在少数需要不一样的地方单独给值；要亮暗各一套，就以 `.dark` 为祖先写覆盖规则，
devkit 的样式检查放行它（`.dark` 是唯一可以不带前缀的类）。窗格标题、工具栏、设置面板这些工作台级的界面不算插件自己的视觉，照常用语义类。

## 主题能改什么

1. **主题只改令牌的值，不改规则**：写了某个插件选择器的主题，那个插件一升级就失效
2. **亮暗就是同一批名字的两套值**（`:root` / `.dark`），没有别的机制；状态栏的亮暗开关只切换 `<html>` 上的 `dark` 类
3. **主题完整的前提是令牌表之外没有写死的语义色**：生态里每多一处写死，就多一处主题永远换不到的地方

## 检查

上面三条不许由 devkit 的样式检查查（`devkit.dev` 构建之后、`devkit.release` 发版之前，对构建后有 `dist/style.css` 的插件都查；
没过的不装进 home、不发版）。检查只在 devkit 里有一份，本仓的插件不另写测试：

- **没有字面默认值**：产物里 `var()` 的默认值只能是另一个 `var()` 或 `currentcolor`。`tw-animate-css` 包里写死的动画缺省值除外，
  那是动画机制的运行时默认，不是设计值，映射文件也改不到
- **颜色类只用令牌**：颜色类里的颜色名必须出自外壳映射文件的条目或本插件样式入口里 `@theme` 注册的名字。两边都在检查时现读现解析，
  不手写名单：外壳的映射文件从插件包目录 `node_modules` 里装的外壳读，令牌加了名字、插件注册了新颜色，检查自动放行
- **范围**：只管 Tailwind 的颜色类。插件域变量与普通 CSS 规则不在范围内；任意值写死（`bg-[oklch(…)]`）是明确的装饰色写法，也不查
