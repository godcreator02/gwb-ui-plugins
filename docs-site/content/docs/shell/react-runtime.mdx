外壳和每个带界面的插件的浏览器侧代码都写 `import … from 'react'`，构建时这几个包名不打包进去，留给页面解析。
解析由两个包分工：**内核**只提供通用的机制——主进程里登记「包名 → 本地文件地址」（`registerImports`），页面动态加载模块之前
把登记的内容注入成 importmap（`prepareImports`），它不认识 React；**外壳**提供 React 本身——自己打包四个文件，自己登记，
升级 React 只发外壳。为什么这样分，见内核仓的轨迹卡 `2026-09-27-browser-imports-service`。

React 没有浏览器能直接加载的 ESM 入口。外壳的 `scripts/build-react.ts` 把四个包名各打成一个 ESM 文件，放进 `dist/react/`；

打包时有两处必须手工处理，漏了都是构建通过、到页面上才报错：

- **具名导出要逐个写出来**。React 的包是 CommonJS，入口再转发到别的文件，esbuild 从中推不出具名成员，直接打包只得到一个 `default`。
  所以 `src/react/` 下每个入口显式列出具名导出，React 加了新 API 就补一行；少一行，用到它的窗格加载时报
  「does not provide an export named …」，整个窗格空白：

- **`react-dom` 里的 `require('react')` 要换掉**。它在工厂函数内部调 `require`，esbuild 提不到顶层，产物里留一个 `__require` 探针，
  浏览器里一运行就报错。构建脚本在文件头加一句 `import`，把探针换成只认 `react` 的同步解析器；认不出探针的形状就让构建失败：

## 外置名单之外的都打包进插件

浏览器侧只有登记过的名字能留成裸的包名。不在名单里的库一律打包进插件自己的 `client.js`：外置了一个页面上没登记的名字，
构建照样通过，到页面上加载时报「Failed to resolve module specifier」。外壳自己的 dockview 也是这样打包进 `client.js` 的：

{/* ref file="../plugins/shell/build.ts" lines="9-13" hash="1c92206b80d2" blob="4dc419913506" */}

从子路径取名单的插件，peer 里的外壳版本要带 `./browser-imports` 这个出口。浏览器侧产物里只许出现页面上登记过的包名，这一条由 devkit 的发版前检查查，
本仓的产物测试不另查：

{/* ref file="../plugins/shell/tests/artifact.test.ts" lines="7-13" hash="b521b950090a" blob="9c8cce9a0c60" */}

别的插件也可以照同样的代码约定提供浏览器模块：导出一个无副作用的名单函数，在主进程里 `registerImports`。
使用方在 peer 里写上提供方、用 cordis 的注入保证提供方先加载完成（先登记），构建时从提供方的名单取外置名。
内核按一次 `registerImports` 交来的整批登记，要么全登记上、要么一个都不登记；同一个名字只能指向一个地址：两个提供方给同名不同地址，
后登记的那一方在 `registerImports` 时抛错；同名同地址算复用。

## 页面怎么准备 importmap

页面这一侧的做法在内核里（内核仓 `apps/desktop/src/preload.cjs` 与 `index.html`），外壳只负责在动态 import 之前调一次。
内核的页面在 import 外壳之前调，外壳在 import 每个窗格插件的 `client.js` 之前调：

{/* ref file="../plugins/shell/src/client/PluginPane.tsx" lines="17-24" hash="a5a81f216f2b" blob="056b20dadf53" */}

每次准备，preload 都向主进程要一份登记表快照，把还没注入过的名字写成一段新的 `<script type="importmap">` 追加进 `<head>`。
所以外壳启动之后才登记的名字，在下一次开窗格时也能用上。同一个页面里注入过的映射不能撤销也不能改：已注入的名字在登记表里变了地址
或被撤销（提供方卸载），准备时以 `GWB_IMPORTS_RELOAD_REQUIRED` 开头的错误拒绝，页面要整页重载（`shell.reload`）后按新的登记表重来，
不会在旧的 React 模块还在使用时悄悄换一份。

## 全页一份 React 换来什么

窗格契约交给插件的是一个 DOM 容器和一个挂载函数，插件在容器里自己 `createRoot`，没有 React 对象在插件之间传递，
所以「全页同一个 React 实例」今天不是正确性的前提。它换来的是字节——带界面的插件不必各带一份 React——以及升级 React 只发外壳一个包。
如果将来契约变成「插件交出 React 组件、由外壳来渲染」，同一个实例就成了前提：两份 React 下 hook 当场报错。
