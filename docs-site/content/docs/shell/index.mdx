外壳是包 `@godcreator/gwb-shell`，源码在 `plugins/shell/src/`：node 侧入口是 `src/index.ts`（构建成 `dist/index.js`），
浏览器侧入口是 `src/client/index.tsx`（构建成 `dist/client.js`）。

## 功能

- **接管内核的页面**：声明自己是外壳，内核页面把 `#root` 交给 `client.js` 的默认导出；外壳卸载或换版本时同步交还。
  见[外壳怎么接管页面](/docs/shell/takeover)
- **窗格注册**：插件在自己的 `apply` 里注册窗格、报名字，外壳补上条目 id 与包名、登记时检查参数，注册表经命令传到页面。见[窗格](/docs/shell/panes)
- **开窗格**：一个窗格开几份看它装着什么内容；开到哪一组、激活已开的还是开新的、预览窗格与换内容，都由纯函数判断。见[窗格](/docs/shell/panes)
- **多桌面与布局保存**：一张桌面一个 dockview 窗格容器，挂载后常驻；布局自动保存、可以起名存，读不回来时停止保存。
  见[多桌面与布局保存](/docs/shell/desktops)
- **状态栏**：桌面、布局、新建、环境与版本、刷新、亮暗，外加标签右键菜单。见[状态栏](/docs/shell/statusbar)
- **样式与令牌**：令牌表 `theme.css`、给插件构建用的类名映射 `theme.reference.css`、外壳自己的两张样式表。
  见[样式](/docs/shell/styles)与[令牌](/docs/shell/tokens)
- **React 运行时**：页面上外壳与所有窗格插件共用的一份 React，经内核登记进 importmap。见[React 运行时](/docs/shell/react-runtime)
- **随包说明书 `gwb-shell`**：给写窗格插件的人与 agent 的接入规范。正本是 `content/docs/outputs/skills/gwb-shell.mdx`，
  生成到 `plugins/shell/skills/gwb-shell/SKILL.md`，说明书插件在时由外壳登记

### 给插件的服务 `ctx.gwbShell`

插件在 `inject` 里写 `gwbShell`，拿到的服务只有两个方法：注册窗格、报自己给人看的名字。两者都登记在调用方的上下文上，

### 命令

外壳的其余能力全部是命令，登记在命令总线上，谁都按名字调：

| 命令 | 做什么 | 谁在调 |
| --- | --- | --- |
| `shell.panes` | 此刻的窗格注册表 `[{ id, title, icon?, client?, style?, kind, entryId, pkg }]`，按注册先后 | 外壳的页面；跨插件开窗格前查 `entryId` 的插件 |
| `shell.plugins` | 报过名字的插件 `[{ title, icon?, entryId, pkg }]` | 状态栏「新建」的分组名；基础界面的插件管理窗格 |
| `shell.env` | 页面每次启动时要的环境 `{ home, styles, startupCss?, versions }` | 外壳的页面 |
| `shell.layout.get`、`shell.layout.save` | 读布局文件；整份替换，写之前校验形状 | 外壳的页面 |
| `shell.reload` | 整页重载全部窗口 | 插件管理窗格升级之后；agent |
| `shell.desktop.list`、`switch`、`new`、`rename`、`delete` | 桌面，见[多桌面](/docs/shell/desktops#命令shelldesktop) | agent、别的插件 |
| `shell.openPane` | 打开任何插件的窗格，见[跨插件开窗格](/docs/shell/panes#跨插件开窗格shellopenpane) | 别的插件、agent |
| `shell.pane.list`、`focus`、`send`、`close` | 所有桌面上开着的窗格，见[窗格命令](/docs/shell/panes#窗格命令shellpane) | agent |
| `shell.pane.sync` | 页面专用：把窗格清单推给 node 侧缓存 | 只有外壳自己的页面 |

窗格容器在页面上，node 侧没有：桌面、窗格与跨插件开窗格这几条先在 node 侧检查参数与目标，再经内核事件转给页面执行，
**回执 `ok` 只代表转发了**，要确认结果稍后再调对应的 `list`。

### 页面上的两个契约

- **内核页面根**：`client.js` 的默认导出 `mountShell(root)` 接收 `#root`，回 `{ dispose() }`。`dispose` 返回时 React 树必须已经卸载，
  见[外壳怎么接管页面](/docs/shell/takeover)
- **窗格插件**：插件的浏览器侧模块导出 `mountPane({ host, shell, pane }, container)`，回 `{ dispose(); retarget?(params) }`。
  这些类型从子路径 `@godcreator/gwb-shell/pane` 用 `import type` 取，见[插件拿到的 args](/docs/shell/panes#插件拿到的-args)

## 依赖

| 依赖 | 怎么用到 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- |
| 命令总线 `gwbCommands`（`@godcreator/gwb-commands`） | 必需依赖，写在 `static inject`；peer | 登记全部 `shell.*` 命令；处理 `shell.env` 时查 `theme.startupCss` 在不在 | 外壳不加载，cordis 在日志里写明在等它 |
| 数据 `gwbData`（`@godcreator/gwb-data`） | 必需依赖；peer | 布局文件存成 gwbData 的文档 `layout` | 外壳不加载：布局没地方存 |
| 说明书 `gwbSkills`（`@godcreator/gwb-skills`） | 局部注入；peer，标 `optional` | 登记随包的 `gwb-shell` 说明书 | 外壳照常运行，只是说明书没登记；说明书插件后加载时补登记 |
| 内核服务 `gwbKernel`（`@godcreator/gwb-kernel-desktop`） | 不写进 `inject`，构造时经 `requireKernel` 取；peer 只为 `import type` | `setShell` 接管页面根、`registerImports` 登记 React、`emit` 把动作推给页面；`dataDir` 与 `version` 给 `shell.env` | 不在 gwb 内核里（普通 cordis 宿主）就在构造时抛错 |
| `cordis` | peer，按值 import `Service` 基类 | 外壳服务的基类，用宿主那一份 | — |
| 命令插件的页面客户端 `@godcreator/gwb-commands/client` | 打包进 `client.js` | 浏览器侧调命令：经内核的 `commands.run` 请求通道走到命令总线；交给窗格插件的 `host.call` 就是它 | — |
| 外观插件的 `theme.startupCss` | 按名字调，不写 peer | 启动时取用户外观样式 | 没装外观插件照常启动，只是不带用户外观样式 |

注册发生在主进程里，摆放窗格在页面上，注册表只能经命令传过去：内核自己一条命令都没有，也不认识任何插件的命令名。
所以命令总线是必需依赖——没有它，外壳就是一个打不开任何窗格的空容器，不如不加载。

## 不做的事

- **不把界面知识放进内核**：内核只转交外壳入口地址、importmap 与事件，注册表、布局、桌面全在外壳里。「内核把窗格表一起推给页面」这类做法不做
- **不替插件改参数**：注册窗格时地址、`kind`、id 不合格就抛错，不改写、不按缺省值登记，理由见轨迹卡
  [窗格地址在注册时检查](/trajectory/2026-09-24-pane-address-check-at-register)
- **没有窗格之间的消息总线、不导出命令名常量、不迁移旧版布局文件**：没有使用者，理由见轨迹卡
  [外壳 0.15 删掉没人用的](/trajectory/2026-09-26-shell-015-drop-unused)
- **不强制暂停隐藏的桌面**：只通知可见性，停订阅、停渲染由插件自己做，见[多桌面](/docs/shell/desktops)
- **不按选择器限定样式范围**：外壳与插件都用类名前缀隔离，见[样式](/docs/shell/styles)
- **独立窗口、把标签拖进另一张桌面的指定位置、快捷键、「已开就跳过去」的设置、桌面排序、在后台打开新标签**：
  想过、先不做，各自在等什么见[路线](/future/roadmap)
