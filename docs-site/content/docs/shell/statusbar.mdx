## 它不在窗格系统里

状态栏是容器底部那一条，也是页面上唯一不属于任何桌面的东西：所以窗格全关掉了它还在，桌面切换器也只能放在这里。它的层级高过桌面上的模态遮罩，
开着模态框也点得到。页面是上下两块：桌面区占满剩下的高度，状态栏固定高度。

桌面区必须带 `min-h-0`：flex 子项缺省 `min-height: auto`，窗格里的内容一高就把状态栏挤出屏幕。

从左到右：

| 项 | 做什么 |
| --- | --- |
| **桌面** | 写着当前桌面的名字；点开是[「桌面」面板](#桌面面板所有桌面与上面的窗格) |
| **布局** | 存下的布局清单：点哪条就恢复到活动容器上，行尾 ✕ 删那条；「把当前布局另存为…」（这一行变输入框，Enter 或失焦保存、Esc 取消，同名覆盖）；「重置布局（当前桌面回到默认布局）」。见[起名存下的布局](/docs/shell/desktops#起名存下的布局) |
| **＋ 新建** | [启动器](#新建启动器)：按插件分组列出全部窗格 |
| （提示）**… · 切过去** | 显示 10 秒，点了切到那张桌面：送到别的桌面没跟过去时写「已送到『X』」；插件或命令要开的工具窗格在别的桌面上时写「『X』在『桌面 N』」 |
| （告警）**布局保存失败** | 只在保存失败时出现，点一下立刻重试 |
| （告警）**布局没读回来，不保存** | 只在布局读不回来时出现，悬停写着原因；点了弹确认框，确认「覆盖」后用当前布局整份写一次、恢复自动保存 |
| **环境** | home 目录的最后一段与 `gwb-kernel <内核版本>`，见[环境与版本](#环境与版本) |
| **刷新** | 整页重新加载，见[刷新与 `shell.reload`](#刷新与-shellreload) |
| **亮暗** | 切 `<html>` 上的 `dark` 类，令牌整套跟着换 |

## 「新建」：启动器

启动器只管开一个新的，「桌面」面板只管切到已开的：一个列表同时做两件事，对文档窗格就说不清点下去是开新的还是切过去。见轨迹卡
[启动器与切换器分开](/trajectory/2026-09-19-launcher-switcher)。

每次点开都**当场取**注册表与插件名表，按插件分组（组名是插件报的名字，没报就是包名），运行中新装的插件不用刷新就在。注册表读不出来时菜单里写
「读不出注册表：原因」，跟「还没有插件注册窗格」分开；插件名表读不出来只让组名退回包名，页面控制台一条 error。

选了一条之后做什么由 `planLaunch` 判断，跟插件开窗格不同的是：目标组固定是活动组，不走「最近用过的同类组」；文档窗格一律开一份新的（key 空串、不带参数，插件画它的默认内容）；
工具窗格当前桌面有就激活，别的桌面上有就切过去激活（这一下是人点的），哪儿都没有就开进活动组。

{/* ref file="../plugins/shell/src/openable.ts" lines="337-359" hash="fa7cf85b3537" blob="66ecfea342ee" */}

**每一行行尾写点下去会怎样**：「＋」开一份新的，「→ 当前桌面」「→ 桌面 X」去已开的那份，这几行左边另有一道色条。行尾问的就是 `planLaunch` 自己，
不另写一份「有没有开着」的判断——两处依据不一致时没有任何现象，只是行尾开始写错。写的是动作不是状态：写「在『X』」这类状态，人还得自己推断点下去会怎样。

{/* ref file="../plugins/shell/src/client/open.ts" lines="53-67" hash="ecaebf98be9e" blob="c3574996f7de" */}

**选了之后菜单不关**（用户定的：常用它连续打开好几个窗格），开完静默重新读取一次清单，点外面或 Esc 才关。点了开在别的桌面上的工具会切桌面，那时菜单还开着，
所以它标了 `data-gwb-status-layer`，切桌面后的 body 检查认得它。

## 「桌面」面板：所有桌面与上面的窗格

切换器与桌面清单是同一个面板，照桌面本来的顺序列出每张桌面与上面的窗格（当前那张标「当前」，不提到最前）。行里没有关闭、送到的按钮：关窗格在标签上，
送到与拉到本桌是拖拽。见轨迹卡[桌面面板](/trajectory/2026-09-19-desk-panel)。

| 操作 | 发生什么 |
| --- | --- |
| 点一张桌面 | 切过去 |
| 点一个窗格 | 激活它；在别的桌面就切过去再激活，没挂载过的先挂载 |
| 右键桌面名，或 F2 | 改名，见[桌面改名与删除](/docs/shell/desktops#桌面改名与删除) |
| 删除钮 | 先确认再删，确认框叠在面板上面；只剩一张时没有 |
| 把窗格行拖到另一张桌面上 | 送过去；拖到当前桌面上就是拉到本桌；拖到「新建桌面…」上就是送到新桌面。悬停在目标上时显示底色，放回它本来那张桌面不接受。放下时按住 Shift 就跟过去 |
| 从桌面上拖一个标签到状态栏「桌面」项上 | 停 500ms 面板自己弹开，再放到哪张桌面上同上；没停够就放开，面板不弹开 |
| 「新建桌面…」 | 这一行变输入框，Enter 或失焦就新建并切过去，Esc 取消；空名用「桌面 N」；新建的那张为空 |
| 什么时候关 | 只有点面板外面或 Esc：上面这些做完面板都留着（用户定的：常用它在桌面之间来回切换） |

它是弹出面板不是下拉菜单：菜单的规矩是点一项就选中并关掉、按键用来跳到以这个字母开头的项，跟改名输入框、拖拽都冲突。radix 的弹出面板缺省还有一条
「焦点移出去就关」：切桌面时外壳把焦点交给新桌面、激活窗格时 dockview 也会挪焦点，所以这一条被拦掉。改名或起名时 Esc 只放弃输入：
radix 的 Esc 监听在 document 的捕获阶段，比输入框先收到，所以面板在这两种时候拦下它。

{/* ref file="../plugins/shell/src/client/DesktopPanel.tsx" lines="177-190" hash="1372e9d3357f" blob="e7cfab83fd6a" */}

**拖的是哪个窗格**：HTML5 拖拽在 dragover 里读不到数据的内容，而「这张桌面接不接」在 dragover 里就得答，所以面板里的行在拖起时把自己记在模块里；
桌面上的标签是 dockview 自己的拖拽，它把正在拖的面板放在页内单例里（外壳的 `client.js` 里只有一份 dockview），放下时还读得到。整组拖不算。

{/* ref file="../plugins/shell/src/client/pane-drag.ts" hash="959a7c6fe9d8" blob="b67fa5972b4c" */}

**面板的清单**：已挂载的桌面从正在运行的容器当场读，没挂载过的从已保存的布局读。点开时读一次；开着的时候桌面清单变了、或外壳又保存了一次（别处开关窗格都会保存），
就重新读——最多慢一个防抖窗口。

## 环境与版本

状态栏上只写 home 目录的最后一段与内核版本（开测试 home 时一眼看出自己在哪），悬停列出 home 全路径与四行版本。每个版本问它自己的出处：
内核版取 `gwbKernel.version`（内核读自己的包清单），外壳版读外壳的包清单，Electron、Node、Chromium 是主进程的 `process.versions`。
这几样在 node 侧回应 `shell.env` 时拼好，页面只负责显示。安装包版本不显示：内核不再提供它，见轨迹卡
[状态栏去掉安装包版本](/trajectory/2026-09-25-statusbar-drop-launcher)。

## 刷新与 `shell.reload`

「刷新」是 `location.reload()`：整页重新加载，重新执行一遍启动流程（取环境、取注册表、读布局文件、恢复），主进程不重启。装了新插件、启停了插件之后点它，比重启整个应用开销小。

`shell.reload` 是同一件事的命令版本，无参数，重载全部窗口：给热升级之后的调用方用——node 侧换成新版本之后，开着的页面用的仍是旧的 `client.js`，
浏览器已经 import 过的模块不会重新加载，只有整页重载才能让页面 import 到新版本。基础界面的插件管理窗格在升级成功、跟着重新加载的条目全部回到运行状态之后调它；
agent 经 MCP 升级完也调它。经页面调它时，页面在回执送回之前就开始重新加载，调用方收不到回执。

{/* ref file="../plugins/shell/src/reload.ts" hash="dd4f07b27b83" blob="a62b7924ba69" */}

{/* ref file="../plugins/shell/src/index.ts" lines="228-249" hash="0ca095827cea" blob="d8029385df74" */}

- **没有窗口回 `ok: false`**，不回成功：回成功的话调用方以为界面刷新了，其实什么都没发生；拿不到 electron 也转成回执
- **`BrowserWindow` 是一个类，`typeof` 是 `'function'`**：取 `getAllWindows` 之前，对象与函数都要接着往下取。只按「是对象」判断，就永远取不到它，
  一直回「不在 Electron 主进程里」；报错要说清是 `BrowserWindow` 不在，还是它在但没有 `getAllWindows`
- **`import('electron')` 的说明符放在变量里**：外壳不装 electron 的类型，运行时它就在主进程里

## 标签右键菜单

| 项 | 出现条件 | 做什么 |
| --- | --- | --- |
| 保持打开 | 预览窗格 | 转成正式窗格，同双击标签 |
| 在旁边再开一份 | 文档窗格 | 用这一份此刻的 key 与参数、`placement: 'side'` 开一份正式的，来源就是这一份；这一份是预览就先转成正式窗格 |
| 送到 ▸ 桌面 X / 新桌面 | 总有，列出这个标签所在那张以外的桌面 | 见[送到别的桌面](/docs/shell/desktops#送到别的桌面拉到本桌)；按住 Shift 选就送完跟过去 |
| 关闭 / 关闭其他 / 关闭右侧 | 总有；组里只有这一个时「关闭其他」灰着，它已在最右时「关闭右侧」灰着 | 同一组里逐个关，插件照常 `dispose` |

菜单挂载到这张桌面的浮层挂载点（桌面切走时跟着隐藏），挂载点在菜单打开那一刻按标签找：标签第一次渲染时还不在桌面 section 里，那时找会退回 `body`。
这个窗格是哪一类问的是最近一次取到的注册表（每次取注册表时同时记下一份），工具窗格没有「在旁边再开一份」：它整页至多一份。

## 关闭窗格

入口：标签上的 ✕（鼠标停在标签上才显示）、标签右键菜单的三项、`shell.pane.close`。关窗格不在「桌面」面板里。

| 情况 | 发生什么 |
| --- | --- |
| 关掉一个窗格 | 插件的 `dispose` 排到 React 提交之外调用，见[一个窗格从注册到关闭](/docs/shell/takeover#一个窗格从注册到关闭)；这一组激活最近用过的那个标签，这是 dockview 自己的行为，外壳没有另写 |
| 组里最后一个标签关了 | 这一组消失 |
| 桌面上最后一个窗格关了 | 桌面变空，外壳不自动开任何窗格；状态栏「新建」随时可用 |
