内核的页面只有一个 `#root` 和一张状态页，它不认识任何界面。外壳是一个普通插件：node 侧告诉内核「页面归我」，
浏览器侧的 `client.js` 被页面 import 之后接管 `#root`。下面这个过程跨两个进程，一步一步看。

## 准备与挂载分成两段

`dispose` 随时可能来：外壳插件还在准备时就被卸载、或者又换了一个版本。所以 `mountShell` 与 `bootShell` 都把工作分成两段：
异步的准备段只取东西、不碰页面；准备完交回一个同步的挂载段，页面上的副作用（主题类、身份标记、命令入口、React 树）都在这一段里一起出现、一起移除。

{/* ref file="../plugins/shell/src/client/shell-mount.ts" hash="e4c16141fbac" blob="e8ed3731b5e6" */}

这个文件就是全部规则：准备完成之前 `dispose` 的，挂载段永不执行；已经挂载的，`dispose` 当场同步卸载；`dispose` 之后才到的准备失败不再报。
内核页面在调完旧外壳的 `dispose` 之后紧接着清空 `#root`，所以 `dispose` 返回时 React 树必须已经卸载完——卸载放进 Promise 就会晚于清空，
React 报 `removeChild` 的 `NotFoundError`。为什么在外壳里改而不动内核换外壳的顺序，见轨迹卡
[换外壳时的报错在外壳里分两层解决](/trajectory/2026-09-17-shell-swap-teardown-order)。

内核这一侧的规矩：后调用 `setShell` 的替换先调用的；没有任何插件调用 `setShell` 时页面显示只读状态页。外壳的 node 侧把 `setShell` 包在 `ctx.effect` 里
（代码见[页面上的 React](/docs/shell/react-runtime#browserimports运行时与构建共用的一份名单)），外壳卸载时自动交还页面根。外壳的测试检查两件事：
`setShell` 收到本包 `client.js` 的地址、外壳卸载时撤销；`dispose` 返回之后清空容器不再出错：

## 启动失败的时候

准备段抛错，`#root` 上只写一句「外壳启动失败：原因」，`dispose` 时连这句一起清掉：

{/* ref file="../plugins/shell/src/client/index.tsx" lines="654-665" hash="f6b71e7938c0" blob="144339d9b11c" */}

会走到这里的是：`shell.env` 没回环境（命令调不通、回执不是 ok）、三张样式表有一张加载不了、注册表取不回来。注册表取失败不当成空表——
空表的意思是「一个插件都没注册窗格」，两件事混在一起，人看到的就是一个空桌面、查不到原因。

{/* ref file="../plugins/shell/src/client/panes.ts" lines="22-39" hash="b2dd836a69e4" blob="35d23289a86a" */}

另外两样取不到不算启动失败：布局文件读不回来就按默认布局打开、这一轮停止保存（见[多桌面与布局保存](/docs/shell/desktops#启动与挂载时从哪份布局开始)）；
外观插件的 `theme.startupCss` 回了失败，外壳照常启动、只是不带用户外观样式，`gwb.log` 里一条 error。

## 一个窗格从注册到关闭

窗格插件只写两样东西：node 侧的 `registerPane`，浏览器侧导出的 `mountPane`。中间的一切——登记、开到哪、取地址、注入样式、import、换内容、清理——都由外壳做。

<PaneMountSteps />

这个过程里几处必须这么写的地方：

- **挂载时当场取注册表**，不用开窗格那一刻的快照：插件可能运行中才加载，布局文件里存的包名也可能是改名之前的。
  注册表里没有这一条（插件卸载了）或注册时没给 `client`，窗格里显示「加载失败：原因」

{/* ref file="../plugins/shell/src/client/panes.ts" lines="14-20" hash="0d94da49505d" blob="2530ca0a34f6" */}

- **样式表先加载完再 import**，而且写在同一个 effect 里：顺序由代码保证，不靠两个 effect 的排列顺序。同一个地址只注入一次、之后不移除

{/* ref file="../plugins/shell/src/client/asset.ts" hash="a516d6664273" blob="875b98ab0c68" */}

- **怎么认 `mountPane` 的句柄**：模块上要有 `mountPane` 函数；句柄是对象、上面有 `dispose` 函数才算契约相符，没有就在窗格里报出它回的是什么；
  `retarget` 可选；插件的 `dispose` 排进微任务、在 React 提交之外调用，抛的错交给调用方记下。`mountPane` 必须同步返回句柄：
  写成 `async` 返回的是 Promise，算契约不符，报错里点名它回的是 Promise、要同步返回

- **挂载 effect 的依赖里故意没有插件参数**：面板参数每轮渲染都是新对象，放进依赖会让插件被反复卸载后重新挂载；换内容走另一个 effect，按稳定序列化比对，
  见[换内容：原地换内容或卸载后重新挂载](/docs/shell/panes#换内容原地换内容或卸载后重新挂载)
