## 一张桌面一个容器，常驻保活

每张桌面是页面上的一个 `section`，里面一个 dockview 窗格容器，外加这张桌面的浮层挂载点。启动时只挂载活动那张，别的桌面第一次切过去才挂载，挂载之后常驻。
不显示的那张加 `visibility:hidden`、`pointer-events:none` 与 `inert`：只是看不见、点不到，DOM、定时器、订阅都还在运行，切回来原样在。

{/* ref file="../plugins/shell/src/client/index.tsx" lines="537-566" hash="d9183338c403" blob="9b2b1fdf837c" */}

桌面的 `section` 上**不许加** `transform`、`filter`、`perspective`、`will-change`：加了之后，里面 `position: fixed` 的浮层定位基准从视口变成这个 section，坐标全错。

**可见性只通知、不强制**。浏览器的节流（暂停动画帧、限流定时器）只作用于整页不可见，不作用于同一页里被 CSS 藏起来的一块；同一页里也没有「暂停一棵子树的 JS」的办法，
要强制只能销毁重建，那就不是保活了。所以外壳按桌面 id 通知 `args.shell.onVisibility` 的监听函数，停订阅、停渲染、停视频由插件自己做。
一个监听函数抛错不影响别的；注册时先回调一次当下的值，还没通知过的桌面按可见算（容器第一次挂载那一刻它必然正显示着）。

{/* ref file="../plugins/shell/src/client/visibility.ts" lines="3-11" hash="75713e4c00d6" blob="2d7af8a39b1e" */}

**窗格在哪张桌面按 DOM 当场查**：往上找带 `data-gwb-desktop` 的 section，不另存一张「窗格 → 桌面」的表——那张表要跟着开、关、移动窗格同步更新，
没同步上也没有任何现象，而容器里的窗格永远是某个桌面 section 的后代。插件拿到的 `args.shell.portal` 也是这样找的：这张桌面的浮层挂载点，
不在桌面里时退回 `document.body`（radix 的缺省）。

{/* ref file="../plugins/shell/src/client/desktop-context.ts" hash="845eca1499f5" blob="898ba65fba5e" */}

模态框只盖住所在桌面的主区：状态栏的层级更高、永远点得到，开着模态框也能切到别的桌面。

## 切桌面

顺序是机制的一部分：

<DesktopSwitchSteps />

只有这几种动作会切桌面：点「桌面」面板里的一张桌面，或别的桌面上的一个窗格；在「新建」里点开在别的桌面上的工具窗格；点状态栏那句「… · 切过去」；
新建桌面（状态栏、`shell.desktop.new`）；删除当前桌面；`shell.desktop.switch`；`shell.pane.focus`（窗格在别的桌面时）；送到时按住 Shift 或
`shell.pane.send { follow: true }`。别的一律不切，包括插件开窗格、`shell.openPane`（要开的工具窗格在别的桌面上时只在状态栏提示）、「新建」里开新的那些、「送到新桌面」。
插件与命令开窗格不切，是因为外壳分辨不出这一下是不是人点的：agent 在后台开一个工具，不该把正在别的桌面上工作的人切走。

## 布局文件

布局文件是 gwbData 里的一份文档 `layout`，一份装三样：每张桌面各自的容器布局（自动保存）、重启回到哪张（`active`）、人手起名存下的布局（`saved`）。

{/* ref file="../plugins/shell/src/layout.ts" lines="7-36" hash="afe31b13aae3" blob="51963d44d83e" */}

node 侧两条命令读写它：`shell.layout.get` 原样回 gwbData 读到的（没存过是 undefined）；`shell.layout.save` 整份替换，写之前校验一遍形状——
页面自己的 bug 拼出的坏文件，不能覆盖磁盘上好的那份。外壳只认 v3，别的版本一律算读不回来，没有迁移。
数据插件只按文档名整份读写、不认识布局的形状；每张桌面里的 dockview 布局外壳也原样存、原样交回 dockview，不解释：

### 什么时候写

- **容器布局一变**：400ms 防抖，然后**按当下重拼整份**再写：回调读的全是引用，迟到的旧定时器写不坏数据；还没挂载的桌面用它已保存的那一条
- **切桌面**：先改 `active` 再立刻整份写一次，然后才切显隐，见上面的分步
- **外壳被卸载之前**：先立刻写一次，最多丢最后 400ms 的挪动
- **保存失败**：状态栏出现「布局保存失败」，点一下立刻重试

每次写的同时把窗格清单推给 node 侧缓存（`shell.pane.list` 读它），停止保存时也照推。

默认布局只在这几处打开：第一次启动、布局读不回来或某张桌面的布局恢复不了、状态栏「重置布局」。默认布局就是注册表里有几个窗格开几个，
全放在同一组里，各占一个标签；工具窗格整页别的桌面上已经开着的不再开。

### 起名存下的布局

状态栏「布局」菜单里「把当前布局另存为…」把**活动那个容器**起名存进 `saved`，同名覆盖（名字就是键）；点清单里哪条就把它恢复到活动那个容器上，
之后照常自动保存。存下的布局是模板，跟正在用的桌面是两回事。

{/* ref file="../plugins/shell/src/layout.ts" lines="158-163" hash="109955f35d9b" blob="51963d44d83e" */}

点开一套存下的布局恢复不了，只报错、不回默认布局：人明确要的是这一套，悄悄换成默认的比失败更糟。「重置布局」逐个移除活动容器里的窗格再打开默认布局，
不用 dockview 的 `api.clear()`——它内部状态对不上时会抛错。

## 桌面改名与删除

| 操作 | 发生什么 |
| --- | --- |
| 改名（「桌面」面板里右键桌面名，键盘上是 F2；`shell.desktop.rename`） | 那一行变成输入框，Enter 确认，Esc 或失焦放弃；名字去掉两端空白，空名不改。改完整份保存一次。用右键不用双击：单击是切过去，双击会跟它冲突 |
| 删除（「桌面」面板里那一行的删除钮） | 只剩一张时没有删除钮。一律先确认：「删除『X』？」，上面有窗格就写「上面 N 个窗格会一起关掉」，空桌面写「这张桌面是空的」 |
| 删除（`shell.desktop.delete`） | 同上但不弹确认（调用方已经决定了），只剩一张时回错；回执 `{ ok, relayed, closed }`，`closed` 是转发那一刻缓存里那张桌面上的窗格数 |

删掉时上面的窗格逐个关掉，插件照常 `dispose`；没挂载过的桌面上的窗格从没加载过插件，连同已保存的布局一起丢弃。删的是当前桌面，就先切到左边相邻那张（最左边那张就切到右边那张）。
删除而不合并是用户定的：窗格里的东西存在各插件自己那里，关掉丢的只是摆放位置，确认框挡住误删；要留下哪个，删之前先送到别的桌面。

## 送到别的桌面、拉到本桌

入口：把窗格拖到状态栏「桌面」面板里的另一张桌面上（面板里的窗格行，或直接从桌面上拖标签）、标签右键「送到 ▸ 桌面 X / 新桌面」、`shell.pane.send`。
dockview 没有在两个容器之间搬面板的接口，所以**送到是一次关闭加一次打开**：

1. 先查这个窗格的定义还在不在注册表里：插件卸载了就不送，console 里一条 warn——源桌面关得掉、目标桌面开不回来，送的话这一份就没了。
   这一步在新建目标桌面之前，送不了时不会留下一张空桌面
2. 两张桌面有没挂载过的，先在后台挂载（不显示）；送到新桌面就先建一张空桌面，不切过去、也先不保存
3. 读好目标桌面的快照，在源桌面关掉这一份（插件 `dispose`），再在目标桌面按 `planSend` 开：工具窗格目标桌面已有同一定义、同一 key 的，就只激活那一份；
   否则按目标组规则（没有来源：最近用过的同类组，否则活动组，桌面空就新建一组）开一份**正式**标签——预览不带过去，文档窗格目标组里有同一内容也照开
4. 当前桌面不变，状态栏显示「已送到『X』· 切过去」10 秒，点了才切；拖放或菜单里按住 Shift、或命令带 `follow: true`，送完跟过去

标题照这一份带过去：插件自己改过的原样带，还是定义的缺省标题（含「(n)」）就按新序号重算。插件的状态只靠参数带过去：步骤 3 里插件被重新挂载，
滚动位置、打到一半的字，插件想保住就得放进 `setPaneContent` 的参数里。

{/* ref file="../plugins/shell/src/openable.ts" lines="361-397" hash="91e54a49f1cd" blob="66ecfea342ee" */}

{/* ref file="../plugins/shell/src/client/open.ts" lines="100-148" hash="04f22e1b03e2" blob="c3574996f7de" */}

默认不跟过去：送走多半是在整理当前桌面，人还要接着在这张桌面上工作，想跟过去多点一下「切过去」就行。

**拉到本桌**：在「桌面」面板里把别的桌面上的窗格拖到当前桌面上，就是送到当前桌面，送到之后它就是活动标签，不涉及切桌面。

## 命令：`shell.desktop.*`

| 命令 | 参数 | 做什么 |
| --- | --- | --- |
| `shell.desktop.list` | 无 | 回 `{ desktops: [{ id, name }], active }`，读磁盘上的布局文件，认不出回一张缺省桌面 |
| `shell.desktop.switch` | `{ id?, name? }` | 切过去；给一个，两个都给按 id，名字重名取第一张 |
| `shell.desktop.new` | `{ name? }` | 新建一张空桌面并切过去，缺省叫「桌面 N」 |
| `shell.desktop.rename` | `{ id, name }` | 改名，`name` 去掉两端空白后非空 |
| `shell.desktop.delete` | `{ id }` | 删除，上面的窗格一起关掉，不弹确认 |

`list` 在 node 侧直接读文件；其余几条经内核事件转给页面执行，**回执 ok 只代表转发了**，要确认结果稍等再 `list`。
`switch`、`rename`、`delete` 转发之前先用磁盘上的文件检查桌面在不在（`delete` 另查「不是最后一张」），不在当场回 `ok: false`，错误里写明用 `shell.desktop.list` 查。
`switch` 的 `id` / `name` 给了却不是非空字符串也当场回错，不改按另一项找：调用方写错了参数，按另一项找到的那张多半不是它要的。
