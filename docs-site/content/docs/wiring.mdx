# 插件之间怎么连

**本页回答**：本仓插件提供哪些服务、命令与事件；注入了哪些服务、是必需还是局部注入、peer 怎么写；按名字调用了别家哪些命令、用了哪些约定通道。

每张表下面是钉码：钉在服务名、`inject` 声明、peer 条目、命令名、事件名、共享 id 这些字面量上，源码里的字面量改了，这一页就报出来。

peer 里写三类：内核包 `@godcreator/gwb-kernel-desktop`（范围包含验证时用的内核）、按值 import 的 `cordis`
（只有外壳按值 import 它）、用到的别的插件。跨仓的插件写 `^<源上 latest>`，同仓的插件写 `workspace:^`、
发版时换成 `^<版本号>`；只是局部注入、缺了只少一部分功能的，在 `peerDependenciesMeta` 标 `optional: true`。
**只按命令名调用的插件不写 peer**：命令总线按名字查找，命令不在就在回执里说明，不需要装好的包——基础界面调
`settings.*`、外壳调 `theme.startupCss` 都属于这种。写进 peer 的不另写 dev，dev 里只剩库与构建工具（react、
tailwind、esbuild、类型包等）。

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需（`static inject`） | `^0.5.0` | 登记本插件的全部命令；处理 `shell.env` 时查 `theme.startupCss` 在不在 | 本插件不加载，cordis 在日志里写明在等它。注册表经命令传到页面，没有命令总线外壳打不开任何窗格 |
| `gwbData` | `@godcreator/gwb-data` | 必需（`static inject`） | `^0.1.7` | 布局文件存成 gwbData 的文档 `layout` | 本插件不加载。布局没地方存，重启一次就没了 |
| `gwbSkills` | `@godcreator/gwb-skills` | 局部注入 | `^0.4.5`，`optional: true` | 登记随包的 `gwb-shell` 说明书 | 外壳照常运行，只是说明书没登记；说明书插件后加载时补登记 |
| `gwbKernel` | `@godcreator/gwb-kernel-desktop`（内核） | 不写进 `inject`，构造时经 `requireKernel` 取 | `^0.7.0` | `setShell` 接管页面根、`emit` 推内核事件、`dataDir` 与 `version` 给 `shell.env` | 不在 gwb 内核里（普通 cordis 宿主）就在构造时抛错 |

peer 里另有 `cordis`（`^4.0.0-rc.9`）：外壳按值 import 它的 `Service` 基类，写成 peer 用宿主那一份。外壳为什么非要
命令总线不可，见[外壳](/docs/shell)「为什么命令总线是必需依赖」一节。

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 命令总线（按名字调） | `@godcreator/gwb-theme` | `theme.startupCss` | 处理 `shell.env` 时取用户外观样式。**先查命令表里有没有这条，没有就不调**：没装主题插件不是问题，调不存在的命令会留一条 warn |
| 内核事件（`gwbKernel.emit` → `window.gwb.on`） | 本插件的页面侧 | `gwb-shell-desktop` | `shell.desktop.switch` / `new` / `rename` / `delete` 转给页面执行 |
| 内核事件（`gwbKernel.emit` → `window.gwb.on`） | 本插件的页面侧 | `gwb-shell-pane` | `shell.pane.focus` / `send` / `close` 转给页面执行 |
| 内核事件（`gwbKernel.emit` → `window.gwb.on`） | 本插件的页面侧 | `gwb-shell-open-pane` | `shell.openPane` 转给页面执行 |
| 共享 id | `@godcreator/gwb-theme` 的外观窗格 | 样式元素 `#gwb-theme-style` | 开机把用户外观样式写进这张样式元素；外观窗格预览时直接改它的内容。两边各写一份字符串、不互相 import |
| 动态 import | 各窗格插件 | 注册窗格时给的 `client` 地址，取导出 `mountPane` | 打开窗格时加载插件的页面侧代码 |
| 内核接口 | 内核 | `gwbKernel.setShell(client.js 的地址)` | 声明自己是外壳、接管页面根；包在 `ctx.effect` 里，插件卸载时交还 |
| 命令（页面 → 本插件 node 侧） | 本插件的 node 侧 | `shell.env`（经 `window.gwb.command`）、`shell.panes`、`shell.plugins`、`shell.layout.get`、`shell.layout.save`、`shell.pane.sync` | 页面开机取环境、取表、读写布局文件、推窗格清单 |
| 动态 import | Electron 主进程 | `import('electron')`，说明符放在变量里 | `shell.reload` 取 `BrowserWindow.getAllWindows()` 逐个重载 |

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 命令总线（按名字调） | `@godcreator/gwb-plugin-manager` | `plugin-manager.list`、`plugin-manager.outdated`、`plugin-manager.search`、`plugin-manager.install`、`plugin-manager.uninstall`、`plugin-manager.update`、`plugin-manager.enable`、`plugin-manager.disable`、`plugin-manager.add-entry`、`plugin-manager.remove-entry` | 插件管理窗格的全部操作 |
| 命令总线（按名字调） | `@godcreator/gwb-settings`（不写 peer） | `settings.all`、`settings.get`、`settings.set`、`settings.delete` | 设置区：列出、看 secret 的明文、保存、删条目或卸载时连设置值一起删（逐项看回执） |
| 命令总线（按名字调） | `@godcreator/gwb-shell` | `shell.plugins`、`shell.reload` | 插件的显示名与图标；升级之后整页重载 |
| 命令总线（按名字调） | `@godcreator/gwb-logger` | `logger.backlog`、`logger.where` | 历史日志、日志文件位置 |
| 内核事件（`gwbKernel.emit` → `window.gwb.on`） | `@godcreator/gwb-logger` 的 node 侧 | `t === 'gwb-logger'` | 实时日志；外壳不转发、不认识日志 |

<Diagram name="baseui-panes" title="基础界面的两个窗格各调哪些命令">

- 基础界面插件的必需依赖只有 `gwbShell`；装了 gwbLogger 才注册日志窗格（`id: 'logger'`），装了插件管理才注册插件管理窗格（`id: 'plugin-manager'`）
- 日志窗格调 `logger.backlog` 取历史、`logger.where` 取日志文件位置；实时日志不经 `args.host`，订阅 `window.gwb.on`、只收 `t` 为 `gwb-logger` 的事件
- 插件管理窗格调 `plugin-manager.list`、`outdated`、`search`、`install`、`uninstall`、`update`、`enable`、`disable`、`add-entry`、`remove-entry`，设置部分调 `settings.all`、`get`、`set`、`delete`，插件的显示名与图标取 `shell.plugins`；升级之后调 `shell.reload` 整页重新加载
- 两个窗格互不 import，只共用 `components/ui` 下的组件

</Diagram>
