# 令牌与颜色：共享规则

本页是**规则正本**：颜色怎么分级、令牌怎么演进、插件域自留地的边界在哪。原理（为什么值全页
一份、映射面怎么工作、开机怎么注表）在[样式与组件](/docs/styles)，本页不重讲。**现存代码
有未追平这些规则的，以本页为准追平；追平之前不改本页迁就现状。**

## 一、两级模型：接缝归令牌，自留地归插件

样式分两级，判据只有一条：**这批样式要不要跨插件一致、要不要跟工作台主题走。**

| | 全局令牌（tokens 包） | 插件域样式 |
| --- | --- | --- |
| 管什么 | **接缝**：背景、前景、主色、卡片、边框、muted、状态色这些跨插件语义 | 插件的产品级视觉词汇——编辑器的高亮色盘、专属图示色这一族 |
| 几份 | 声明面全页**唯一一份**，由外壳注入 | 住插件自己的产物，各插件各的 |
| 跟主题 | 换表全生态一起变 | 默认不跟；靠桥接大部分免费继承 |

**唯一性只属于接缝层**。「参与主题的那张表全页一份」指的是这层，不是「所有样式词汇收归
令牌包」——把插件域样式灌进令牌包，接缝就被污染成一锅粥。

### 归属判据：三个问题，从最便宜的问起

拿到任何一个新样式值，依次问，问到哪层停哪层（**先问「能不能不上收」**，别反过来）：

| 问 | 停在哪层 | 典型 |
| --- | --- | --- |
| 一次性装饰？ | **任意值写死**（`bg-[oklch(…)]` 或插件内一段 CSS），完事 | 一处用的小点缀 |
| 插件内多处、只有本插件有这个视觉概念？ | **插件域令牌**（见第四节两段制） | 日志来源点色、编辑器高亮盘 |
| 跨插件要一致、主题要管？ | **全局令牌**（本包） | 警告色、间距基数、阴影档 |

插件域令牌的**上收时机**：第二个消费者出现的那天（跟组件 registry 同一个判据）。

## 二、颜色的分级判据

拿到任何一个新颜色，先问一句：**换主题时它该不该变？**

| 判据 | 性质 | 走法 |
| --- | --- | --- |
| 该变，且跨插件要有同一含义（警告、危险、品牌） | **语义色** | 转正进令牌：声明面加值（亮暗两套）＋映射面加映射，发版；插件升依赖重编后写语义类 |
| 该变，但眼下只有本插件在用 | 先映射既有语义 | 这种色多半就是 accent / muted / destructive 的别名；确无对应再考虑加令牌 |
| 不该变（纯装饰，声明不跟主题） | **装饰色** | 明示写死：任意值语法或插件内一段普通 CSS，经得起一句「为什么它不跟主题」 |

**禁止三条**：

1. **禁止用 Tailwind 内置调色板类表达语义色**——调色板查的是出厂表，不查令牌表，换主题
   不跟随，且无报错
2. **禁止语义色写死字面量**（hex / oklch）——理由同上
3. **禁止插件私有令牌包**——插件自己那份「映射面＋值表」等于再造一张表：值进不了页面唯一
   那份，主题换不到它；要让它被注入就得改外壳，回到中心登记。令牌包全生态一个，
   特殊颜色的出口只有上表两条

## 三、令牌演进三律

令牌的名字清单是**全生态的公共契约**，演进只许两个方向：

1. **改值随便**——那是主题的本职。改声明面的值、发版、home 升级，全部插件零重编当场变
2. **加名随便**——向后兼容。加了新令牌，不用它的插件零动作；用它的插件升依赖重编
3. **删名禁止**——删掉一个名字，所有还写着那条 `var()` 的插件**当场读空，静默**。名字
   一旦发出去就只有「废弃但保留」一条路

## 四、插件域自留地的规矩：两段制

插件有自己的视觉体系**完全合法**（重界面的插件必然如此），落地形态是**两段**，都住在插件自己身上：

1. **值段**——`src/client/tokens.css`：插件域变量的声明（名字带插件前缀不撞全局，挂 `:root`
   保证 portal 出去的浮层也读得到），桥接优先：默认派生全局令牌（`--插件域变量:
   var(--accent)`），需要偏离的少数局部覆盖；亮暗自适配用 `.dark` 当祖先写覆盖规则
   ——产物守卫预期并放行这个用法。
2. **映射段**——样式入口尾部追加 `@theme inline { --color-插件域名: var(--插件域变量) }`，
   注册本插件专属的工具类（`baseui:bg-src-plugin` 这种）；inline 内联，键名即使被前缀
   改写也不影响，产物直接查插件域变量，零 fallback。

活例：baseui 的日志来源点色（`src/client/tokens.css` + 入口映射段）。第三条老规矩照旧：
**接缝部分（窗格标题、工具栏、设置面板这些工作台级 UI）不属于自留地**，照常走语义类。

## 五、主题的规矩

1. **主题只碰令牌，永不碰规则**——写任何具体插件选择器的主题都是野路子：那个插件一升级，
   主题就烂
2. 亮暗＝同一批名字的两张值表（`:root` / `.dark`），没有别的机制；用户级换肤走 theme 插件
   的自定义 CSS，压在一切之上
3. 主题完整性的前提是**表外无值**：生态里每多一处写死的语义色，主题就多一个永远换不到
   的死角

## 六、守卫

第二节的三条禁止，由每个插件的产物守卫钉死（`tests/artifact.test.ts`）：

- **零字面 fallback**：产物里 `var()` 的 fallback 必须是 var() 引用或 `currentcolor`
  关键字；字面量即红。豁免 tw-animate-css 包内写死的机制缺省（`--tw-animation-*` /
  `--tw-enter-*` / `--tw-exit-*` / 简写里的 `--tw-ease,ease`）——那是动画机制的运行时
  默认，不是设计值，映射面够不着
- **颜色类白名单**：颜色工具类选择器的色名必须在「令牌包映射面条目 ∪ 本插件入口
  @theme 自注册」之内——**两边现扫解析，不手写名单**，令牌加名或插件自注册守卫自动放行。
  特殊色名（transparent / inherit / current）与非色形态（字号、对齐、边侧、宽度）豁免
- **管辖边界**：只管 Tailwind 颜色工具类这一族；插件域变量与普通 CSS 规则不在射程内，
  第四节的自留地不受影响；任意值写死（`bg-[oklch(…)]`）是明示的装饰色出口，也不在射程

配套的度量衡国有化（tokens ≥0.1.1）：出厂主题被用到的键全部经映射面送值，间距 / 字重 /
字距 / 白黑 / 阴影全档 / 过渡 / 容器断点全部可主题化——**升 Tailwind 大版本时按映射面
头注重核键名**。
