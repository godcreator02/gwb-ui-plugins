# 令牌与颜色：共享规则

本页是**规则正本**：颜色怎么分级、令牌怎么演进、件域自留地的边界在哪。原理（为什么值全页
一份、映射面怎么工作、开机怎么注表）在[样式与组件](/docs/styles)，本页不重讲。**现存代码
有未追平这些规则的，以本页为准追平；追平之前不改本页迁就现状。**

## 一、两级模型：接缝归令牌，自留地归件

样式分两级，判据只有一条：**这批样式要不要跨件一致、要不要跟工作台主题走。**

| | 全局令牌（tokens 包） | 件域样式 |
| --- | --- | --- |
| 管什么 | **接缝**：背景、前景、主色、卡片、边框、muted、状态色这些跨件语义 | 件的产品级视觉词汇——编辑器的高亮色盘、专属图示色这一族 |
| 几份 | 声明面全页**唯一一份**，由外壳注入 | 住件自己的产物，各件各的 |
| 跟主题 | 换表全生态一起变 | 默认不跟；靠桥接大部分免费继承 |

**唯一性只属于接缝层**。「参与主题的那张表全页一份」指的是这层，不是「所有样式词汇收归
令牌包」——把件域样式灌进令牌包，接缝就被污染成一锅粥。

## 二、颜色的分级判据

拿到任何一个新颜色，先问一句：**换主题时它该不该变？**

| 判据 | 性质 | 走法 |
| --- | --- | --- |
| 该变，且跨件要有同一含义（警告、危险、品牌） | **语义色** | 转正进令牌：声明面加值（亮暗两套）＋映射面加映射，发版；件升依赖重编后写语义类 |
| 该变，但眼下只有本件在用 | 先映射既有语义 | 这种色多半就是 accent / muted / destructive 的别名；确无对应再考虑加令牌 |
| 不该变（纯装饰，声明不跟主题） | **装饰色** | 明示写死：任意值语法或件内一段普通 CSS，经得起一句「为什么它不跟主题」 |

**禁止三条**：

1. **禁止用 Tailwind 内置调色板类表达语义色**——调色板查的是出厂表，不查令牌表，换主题
   不跟随，且无报错
2. **禁止语义色写死字面量**（hex / oklch）——理由同上
3. **禁止件私有令牌包**——件自己那份「映射面＋值表」等于再造一张表：值进不了页面唯一
   那份，主题换不到它；要让它被注入就得改外壳，回到中心登记。令牌包全生态一个，
   特殊颜色的出口只有上表两条

## 三、令牌演进三律

令牌的名字清单是**全生态的公共契约**，演进只许两个方向：

1. **改值随便**——那是主题的本职。改声明面的值、发版、home 升级，全部件零重编当场变
2. **加名随便**——向后兼容。加了新令牌，不用它的件零动作；用它的件升依赖重编
3. **删名禁止**——删掉一个名字，所有还写着那条 `var()` 的件**当场读空，静默**。名字
   一旦发出去就只有「废弃但保留」一条路

## 四、件域自留地的规矩

件有自己的视觉体系**完全合法**（重界面的件必然如此），规矩三条：

1. **桥接优先**：件域变量默认指向全局令牌（件域变量取 `var(--accent)` 这类值），需要
   偏离的少数再局部覆盖——自留地的大部分由此免费继承主题与亮暗
2. **亮暗自适配用 `.dark` 当祖先**写自己的覆盖规则——产物守卫预期并放行这个用法
   （页面级亮暗标志只以祖先的身份出现）
3. **接缝部分照常走语义类**：件的窗格标题、工具栏、设置面板这些工作台级 UI 不属于自留地

## 五、主题的规矩

1. **主题只碰令牌，永不碰规则**——写任何具体件选择器的主题都是野路子：那个件一升级，
   主题就烂
2. 亮暗＝同一批名字的两张值表（`:root` / `.dark`），没有别的机制；用户级换肤走 theme 件
   的自定义 CSS，压在一切之上
3. 主题完整性的前提是**表外无值**：生态里每多一处写死的语义色，主题就多一个永远换不到
   的死角

## 六、守卫（拟建）

第二节的三条禁止，将由产物守卫钉死（尚未落地，落地后本节改写实况）：

- **白名单制**：件产物里凡颜色工具类的选择器，色名必须在「令牌映射面登记过的语义色名」
  之内
- **名单不手写**：守卫解析令牌包映射面的条目动态生成，令牌加名守卫自动放行——守卫与
  正本不漂
- **管辖边界**：只管 Tailwind 颜色工具类这一族；件域变量与普通 CSS 规则不在射程内，
  第四节的自留地不受影响
