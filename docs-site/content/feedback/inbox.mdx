# 投来的反馈

**本页回答**：别的仓在用这个仓的东西的过程中投来了什么意见。

一条一节，往末尾追加，不需要命令：

```text
## <yyyy-MM-dd> <一句话标题>

来源：<哪个仓 / 哪次会话>

<碰到什么、期望怎样、觉得该改哪儿>
```

处理完由本仓删掉那一节——这里是临时存放处不是档案，定下来的判据写进轨迹卡。本仓自己反复做的操作候选
不投这儿，在同区的 [孵化](/feedback/hatch)。

## 2026-09-24 插件管理 0.9：全部更新的回执里有 dependents，可以在窗格里列出来（可选）

来源：总控台会话（生命周期插件仓 `gwb-lifecycle-plugins` 的规格「插件之间写 peer」，插件管理 0.9.0 与 devkit 0.18.15 同一批发布）。

`plugin-manager.update` 的回执有 `dependents: { pkg, entries }[]`——`pnpm add` 前后真实目录变了、本身没被升级的包
（多半是 peer 写了被升级包的插件）会在升级的包重新加载之后一起重新加载，`entries` 与 `updated[].entries` 同形。
基础界面插件管理窗格的 `describeUpdateAll` 可以把它列出来；全都最新时是空数组。这一条是可选的，别的几项已处理完。
