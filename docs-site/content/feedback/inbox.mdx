## 2026-09-13 总控台会话：首开后的自动落盘没发生（隔离 home 上连续三个开机）

来源：总控台会话（验「新建桌面出生为空」时撞见，shell 0.4.4 与 0.4.5-dev 都在）。

现象：`devkit.home.new` 起的隔离 home（窗口从不进前台），开机铺完默认窗格之后，
**防抖落盘从未发生**——`data/shell/layout.json` 不存在，`gwb.log` 里 `shell.layout.save`
只有「登记上了」没有一次执行。直到切桌面 / 新建桌面触发**同步 flush** 才第一次落盘。
同一时段零报错，状态栏也没有「布局没存上」（说明 promise 没走到失败分支，更像定时器
根本没醒）。

两个怀疑，未判别：

1. occluded 窗口的计时器节流——devkit 起 home 带了 `--disable-backgrounding-occluded-windows`，
   但那面挡的是渲染判隐藏，`setTimeout` 节流是否也被挡没查过
2. `onWellReady` 里订阅 `onDidLayoutChange` 排在 `openDefaults` **之后**——若 dockview 在
   `addPanel` 里同步发事件，铺默认那三下全发生在订阅存在之前，一个都收不到

复现：起一个隔离 home → 什么都不动 → 读 `<home>/data/shell/layout.json`（没有）。
default home 平时看不见这条，因为人一交互（开/关/拖格）就有活订阅里的事件，照常落盘。

判别实验也现成：往 `onWellReady` 里订阅之后手动 `api.addPanel` 一次看 `scheduleSave`
醒不醒——醒则是怀疑 2，不醒则是怀疑 1。

## 2026-09-17 总控台会话：窗格容器的 data-gwb-plugin 取自布局存档，包改名后一直是旧名

来源：总控台会话（修 default 里「单元」格整片失样时查出来的；unit-folder 那头已在 0.6.0 改用类名前缀，
不再依赖这个属性，所以这边不急）。

现象：`PluginPane` 挂的 `data-gwb-plugin={pluginKey}`，`pluginKey` 来自 dockview 面板 params，也就是
布局存档里存下的那份，不是现场查注册表。default 的 `shell.layout.get` 里，换 scope 之前开的格全都还是
`@godcreator02/gwb-*`（单元、日志、站内预览、站监控、外观、插件源），而 `entryId` 没变、格照样挂得上。
于是属性上的「身份」对不上现在的包名，谁也不报错。

影响：前缀方案下属性「只是身份标记」，样式不受影响；但注释里说它是给探针、样式调试「认件的把手」，
这个把手在老存档上指错了件。另外 `saved` 里那套叫「88」的布局引的 plugins / hello / status 是早没了的件。

建议（未判，供参考）：挂载时用 `fetchPaneModule` 回来的现场包名覆盖 params 里那份；或读存档时按
`entryId` 把 `pluginKey` 刷成当前值，顺手在下次落盘时写回。

复现：`shell.layout.get` 看任何一个换 scope 之前开过的格的 `params.pluginKey`。

## 2026-09-24 要跟插件管理 0.9：用到的插件改写进 peer，list 换成 unmetPeers，update-all 回执加 dependents

来源：总控台会话（devkit 仓规格「插件之间写 peer」，插件管理 0.9.0 与 devkit 0.18.15 同批发）。

插件管理 0.9.0 是破坏性版本，baseui 的 dev 写的 `^0.8.0` 发完就出范围，下次发版 `devkit.release` 会拦。要做的：

1. **依赖改写法**：插件用到的别的插件（经 `ctx.inject` 用它的服务、或 import 它的类型）写进 `peerDependencies`，
   写 `^<源上 latest>`；只是可选使用的在 `peerDependenciesMeta` 标 `optional: true`。dev 里不再写这些插件。
   baseui 对应：外壳 `@godcreator/gwb-shell` 必需，日志、插件管理可选。`devkit.release` 查 peer 里的插件与源上 latest
   在不在同一条线（0.x 比次版本号，≥1 比主版本号），不在就拒
2. **`plugin-manager.list`**：每个包的 `unmetRequires` 删了，换成 `unmetPeers: { pkg, range, installed? }[]`——插件 peer 里
   （内核包与 cordis 除外）home 里没满足的包：没装（optional 的没装不算）、或装着的版本不在范围里。没装时没有 `installed`。
   baseui 目前不读 `unmetRequires`，代码不用改；想在已装列表上标出来可以读这个字段
3. **`plugin-manager.update-all`**：回执新增 `dependents: { pkg, because, entries }[]`——peer 写了被升级包的插件会在升级的包
   重新加载之后一起重新加载，`because` 是它 peer 里哪个包导致的，`entries` 与 `updated[].entries` 同形。
   `describeUpdateAll` 可以把它列出来；字段一直都有，失败或全都最新时是空数组
4. pnpm 由插件管理与 devkit 运行时一律带 `pnpm_config_auto_install_peers=false`，home 里没装的 peer 不会被自动装进来

规矩正本：devkit 文档站的依赖规则页与说明书 `gwb-release`。

## 2026-09-25 补充「要跟插件管理 0.9」那条：外壳、主题也要把用到的插件写进 peer，命令总线同样写

来源：gwb-devkit（devkit 仓交接页「插件之间的运行时要求写 peer」，总控台会话），2026-09-25。插件管理 0.9.0、devkit 0.18.15 起生效，源上现在是插件管理 0.11.0、devkit 0.19.1。

插件运行时用到的别的插件，从 devDependencies 挪到 peerDependencies，范围写 `^x.y.z`，下限写开发、验证时用的那一版；同一个仓里的插件写 `workspace:^`，发版时换成 `^<版本号>`。「用到」指：经 `ctx.inject` 用它的服务、经命令总线 `@godcreator/gwb-commands` 登记命令、用外壳 `@godcreator/gwb-shell` 注册窗格或样式令牌、import 它的类型。只用 `ctx.inject([...], fn)` 局部注入、缺了只少一部分功能的，在 `peerDependenciesMeta` 里标 `optional: true`；只按命令名调它的命令的不用写。写进 peer 的插件不再另写 dev：插件仓里 pnpm 会把 peer 装进 `node_modules`，类型从那里取。

- peer 里只许三类：按值 import 的 `cordis`、内核包 `@godcreator/gwb-kernel-desktop`、别的插件（清单 `keywords` 含 `gwb-plugin`）。库、接口定义包、构建工具照旧写 dev 或 `dependencies`
- 清单字段 `gwb.requires` 已删：插件管理不再报它，发版检查也不再查
- 发版检查（devkit 0.18.15 起）：peer 里每个 `@godcreator` 插件的范围要是 `^x.y.z`，并且和源上 `latest` 在同一条线（0.x 比次版本号，≥1 比主版本号），不在同一条线就拒；peer 里有这三类以外的包也拒
- home 里关掉了 pnpm 自动补装 peer：插件管理、`devkit.home.new`、`devkit.dev` 在 home 里运行 pnpm 时都带环境变量 `pnpm_config_auto_install_peers=false`。peer 里的插件 home 里没装，不会被顺带装上，由 `plugin-manager.list` 每个包的 `unmetPeers`（`{ pkg, range, installed? }`）报出来，只报告、不拦加载；在隔离 home 里验证时，peer 里的插件要自己装上
- 升级一个插件时，peer 写了它的插件会被 pnpm 装进新目录，插件管理在同一次升级里把它们一起重新加载（回执里的 `dependents`）

本仓要改的：

上面 2026-09-24「要跟插件管理 0.9」那条只写了 baseui，这里补齐全仓：

- `gwb-shell`：dev 里的命令总线、数据 `@godcreator/gwb-data`、说明书 `@godcreator/gwb-skills` 挪进 peer
- `gwb-theme`：dev 里的命令总线、设置 `@godcreator/gwb-settings`、同仓的外壳（peer 写 `workspace:^`）挪进 peer
- `gwb-baseui`：照 09-24 那条（外壳必需，日志、插件管理可选，外壳写 `workspace:^`）；插件管理的范围要和源上 latest 同一条线（现在是 0.11.0）
- 经命令总线登记命令也算用到，命令总线写进 peer、必需

随适配内核 0.6 那一轮一起改、一起发，版本号照说明书 `gwb-release` 升。规矩正本是 devkit 文档站的规则页「用到的插件写 peer」与说明书 `gwb-release`（`run skill.read {"name":"gwb-release"}`）。
