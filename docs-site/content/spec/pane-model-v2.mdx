# 窗格模型第二版

**本页回答**：外壳的窗格系统改成什么样——每个操作按下去会发生什么、为什么这样定（参考了谁）、插件那头的接口怎么变、分几期做、做到什么算完。

**由来**。2026-09-19 在块笔记仓的会话里，人说窗格的绑定、新建、跳转「用起来比较不合直觉」：什么时候复用已有窗格、什么时候新开、开在哪、开完整片自动缩放、新建桌面后开不出东西、会被切到别的桌面；并且认为笔记这种窗格就该能开多份、能从 A 桌面送到 B 桌面，现在的规则像是自己编的。那边读代码查出了几处根因（见下文「现状」），人要求照成熟产品完整重设计一版，每条行为标出参考来源。

**它推翻了本仓几条写下的判据，并且改外壳对插件的接口**（`registerPane` 的形状、`mountPane` 的桥、`shell.openPane` 的参数，另加几条命令）。这些是别的插件 inject 的那一面，2026-09-19 人已逐条拍板（见文末「已拍板」），可以按「分期」开工。

## 现状（查证过的）

这一节是读代码与 dockview 源码查出来的，没有在真工作台里复现过。

**一、窗格的身份在打开那一刻就定死了。** 外壳认「这份内容开着没有」靠打开时给的 `key`（`openable.ts` 的 `planOpen`：已开的份里有 `p.key === want` 就聚焦）。可有的窗格像浏览器标签：块笔记的正文窗格点引用是原地换页，key 与参数却一直停在最初那一块。桥上只有 `setPaneTitle` 与 `keepPane`，插件没法说「我现在装的是别的了」。后果：再打开最初那块会聚焦到一个早已走开的窗格；打开它现在显示的那块又会多开一份；整页重载后回到最初那块。

**二、聚焦看全局，预览与摆放只看本桌，于是会被切走。** `wellHub.openInstances` 把所有桌面的窗格聚在一起喂给 `planOpen`，key 命中别的桌面就 `focusAcross` 切过去（shell.mdx 称之为「任务栏语义」，判据「桌面是分组不是宇宙」）；预览槽与落位只看当前容器。后果：新建桌面（会自动切过去、是空的）后在状态栏点「打开窗格 → 块笔记」，因为块笔记在桌面 1 开着，直接被切回桌面 1——新桌面上开不出它。

**三、新窗格摆在哪，跟你在哪儿点的无关，还会挤压整张桌面。** `placeNext` 按「这个窗格定义此刻在本容器开了几份」分三档：0 份落活动组当标签；1 份给 `{ direction: 'right' }`、不给参照；2 份以上叠在最后一份非基名实例下面。shell.mdx 说第二档「相对当前活动的那一个窗格」，但 dockview 8.3.1 的 `_doAddPanel` 里不带参照的方向走 `orthogonalize`，贴的是**整个容器的边**，整片布局重新分宽——这就是「开了以后窗格自动缩放」。就算带了参照（第三档），`addPanel` 走的 `createGroupAtLocation` 不给尺寸时用 `Sizing.Distribute`，**同一排的组全部均分**，照样牵动别的组；dockview 里只有拖放那条路（`moveGroupOrPanel` 用 `dropSizing`）才是「只切参照组的一半、兄弟不动」，源码注释引的是它自己的 issue #1612。第一档落「活动组」，活动组可能是别的插件的窗格，于是新窗格盖住了它。

**四、外壳不知道是谁发起的打开。** 桥上的 `openPane` 在 `plugin-panel.tsx` 里只绑了条目与窗格 id，没带发起的那个窗格；跨插件的 `shell.openPane` 走 node 半转发，更不知道来源。所以「开在来源旁边」根本无从做起。

**五、状态栏那个「打开窗格」一个列表干两件事。** 它列的是窗格**定义**，点下去走同一个 `planOpen`：已开（任何桌面）就切过去聚焦，没开就开「没带 key 的那一份」。对工具窗格这够用；对文档窗格，「没带内容的那一份」本身就是个奇怪的东西，而它又兼着切换。另外它用的是开机那一刻的注册表快照（`prepareShell` 里取一次），热装的插件要点「刷新」才出现。

**六、窗格不能在桌面之间挪，桌面不能改名、不能删。** 每张桌面是一个独立的 dockview 实例，dockview 没有跨实例搬窗格的接口；外壳也没提供关了重开以外的办法。桌面命令只有 list / switch / new。

**七、插件已经在自己补洞。** 单元文件夹的原文窗格自己维护了一个「焦点原文窗格」（`gwb-unit-folder` 的 `client/selection.ts`：有焦点窗格就经总线点名、没有就广播再 `openPane`），它的「Ctrl+单击再开一份」随 shell 0.7 收紧 `PaneSpec` 休眠了，调用处还留着已经不被认的 `duplicate: true`。块笔记则把 key 当内容用、内部却在导航（见一）。外壳缺「同类窗格最近在哪一组」这个概念，插件只能各造各的。

**八、预览窗格每个容器一个，不是每组一个。** 两列正文各自想要一个可被顶掉的预览标签时，只能共用一个。

## 设计原则

每条一句话，后面是它照着谁。参考来源的编号见文末「参考来源」。

1. **窗格分两类：工具窗格与文档窗格。** 工具窗格（日志、插件管理、外观、备份、单元树、站监控）一张桌面至多一份，打开就是把它显示出来；文档窗格（笔记正文、查询视图、文件原文、站内预览）可以开多份，每份装一个内容，能在里面走来走去。照 VS Code 的视图（住在视图容器里）与编辑器（住在编辑器组里）之分 [R6]、JetBrains 的工具窗口与编辑器标签之分 [R20]。
2. **文档窗格的身份是它此刻装的内容，由插件上报。** 像浏览器标签页：地址随导航变，每个标签页有自己的前进后退 [R13]；Obsidian 的标签页也各有一条历史 [R10]。（VS Code 的前进后退缺省是跨编辑器的一条全局历史 [R27]，它的编辑器里不会原地换文件，所以这一条照浏览器与 Obsidian。）外壳不猜内容，插件换了内容就报一声；历史本身归插件管。
3. **本桌优先：只有显式动作才切桌面。** 打开窗格只在当前桌面里找、在当前桌面里开；别的桌面开着同一内容也不跳过去。照 VS Code `workbench.editor.revealIfOpen` 默认关：已在别的组开着也在活动组再开一份 [R1]。Windows 让人选任务栏与 Alt+Tab 只显示本桌面的窗口还是所有桌面的（二手来源说默认只显示本桌面）[R18]；macOS 默认会切到应用所在的空间（二手来源），但专门留了开关 [R19]——「要不要被拽去别处」在参考产品里都是可选的，不是唯一路径。
4. **新东西落在你点的地方旁边，不挤别人。** 新标签插在当前活动标签右边 [R4]；「开到旁边」先找相邻的组、有就复用，没有才新建 [R3][R20]；一次操作只动一处。
5. **启动与切换分开。** 「开一个新的」和「切到已开的」是两个入口：操作系统的开始菜单与任务栏 / Alt+Tab；VS Code 的「打开的编辑器」视图与 Ctrl+Tab 专管切到已开的 [R7]。
6. **移动是一等动作。** 窗格能送到别的桌面：Windows 任务视图「移动到」[R15]、Chrome「将标签页移至其他窗口」[R14]、VS Code「移到下一组 / 移到新窗口」[R8]、Obsidian「移到新窗口」[R11]、GNOME 把窗口移到别的工作区 [R29]。（删除桌面时窗格怎么办是另一回事，人定的是一起关掉，见「桌面」一节。）
7. **预览是每组的快速翻看。** 每组至多一个预览标签，下一次预览打开顶掉它，开始用它就转正 [R2]。本仓 0.x 已经照 VS Code 做了预览，这一版只把它从「每容器一个」改成「每组一个」，与 VS Code 一致。

## 名词

本页新用到的词。沿用[术语表](/docs/glossary)里的窗格容器、窗格、桌面、预览窗格、布局文件。

| 词 | 意思 |
| --- | --- |
| 窗格定义 / 窗格实例 | 定义是注册表里的一条（插件 × 窗格 id）；实例是容器里开出来的一个标签。沿用 shell.mdx「定义与实例是两回事」 |
| 工具窗格 / 文档窗格 | 注册时 `kind` 声明的两类，见原则 1 |
| 组 | dockview 的 group：一排标签共用的那一块区域。一张桌面上可以有好几组，分屏就是多组并排 |
| 来源窗格 | 发起这次打开的那个窗格实例：插件经桥调 `openPane` 时就是它自己；跨插件命令带 `from` 时是 `from` 指的那个；状态栏与不带 `from` 的命令没有来源 |
| 目标组 | 这次打开落在哪一组，按下文「目标组怎么定」算 |
| 侧边组 | 某一组右边紧挨着的那一组 |
| 最近用过的同类组 | 当前桌面上，最近一次被激活、且装着同一窗格定义的实例的那一组 |
| 内容 key | 文档窗格此刻装的内容的标识，插件给的不透明字符串；工具窗格也有，缺省空串 |

### 目标组怎么定

所有「在当前桌面开一个窗格」的操作都先算目标组。输入是：窗格定义、放法（`placement`）、来源窗格（可能没有）、在哪张桌面（有来源就是来源所在的桌面，否则是当前桌面）。

**`placement: 'side'`（开到旁边）**：基准组是来源窗格所在的组（没有来源就用这张桌面的活动组）。基准组右边已经有侧边组 → 目标组就是它；没有 → 把基准组对半分，右半边成为新的一组，就是目标组。参考 VS Code「在侧边打开」：在首选方向上找相邻组、有就复用，没有才新建，方向缺省向右 [R3]；JetBrains「Open in Right Split」在已有右分屏时也是开进那一个 [R20]。

**`placement: 'auto'`（缺省）**，按顺序取第一个成立的：

1. 来源窗格与要开的是**同一个窗格定义** → 来源窗格所在的组（笔记里 Ctrl+单击，新标签就开在这一列）
2. 这张桌面上有**最近用过的同类组** → 那一组（从查询视图里点一条结果，落到你最近在用的那一列正文里）
3. 有来源窗格 → 照 `'side'` 算（从单元树里第一次点开文件，原文开在单元树旁边，不盖住单元树）
4. 这张桌面有活动组 → 活动组
5. 桌面是空的 → 新建一组

第 2、3 条对应 VS Code 里编辑器只开在编辑器组里、不会盖住视图容器里的视图 [R6]；`revealIfOpen` 的查找也是按组的最近激活顺序来的 [R1]。

**对半分只动基准组**：新组拿走基准组的一半宽，其余组的宽高一个像素不变。今天那种「不带参照、贴整个容器的边、整片重新分宽」的放法（现状三）**不再出现**：每次新建组都带 `referenceGroup` 或 `referencePanel` [R23]。

实现提示（dockview 8.3.1）：光带参照不够，`addPanel` 带参照新建组时不给尺寸会让同一排全部均分（现状三）。能做到「只切一半」的现成路径是拖放用的那条（`dropSizing`），所以可以先把新窗格当标签开进基准组、再用 `panel.api.moveTo({ group, position: 'right' })` 挪到它右边；或者显式给 `initialWidth` 为基准组宽的一半。两条都要在隔离 home 里量过再定。

### 打开窗格

入口有三个，走同一张表：插件桥上的 `shell.openPane(paneId, options)`（来源是它自己）、跨插件命令 `shell.openPane { entryId, paneId, from?, … }`、状态栏「新建」（没有来源，规则另见那一节）。

选项：`key?`（内容 key，缺省空串）、`params?`（交给这一份的参数，可 JSON 序列化，照旧跟着布局落盘）、`preview?`（放进预览标签）、`placement?`（`'auto' | 'side'`，缺省 `'auto'`）。「新标签」不单设一档：不要预览、放法缺省，就是在目标组开一个新的正式标签。

**文档窗格**，先算出目标组，只在**目标组**里查重：

| 目标组里 | 要预览？ | 发生什么 | 参考 |
| --- | --- | --- | --- |
| 有一个标签的 key 等于要开的 key | 否 | 激活那个标签；它若是预览标签，转正 | [R1][R2] |
| 同上 | 是 | 激活那个标签，不改它的预览状态 | [R2] |
| 没有，组里有预览标签 | 是 | 原地换掉预览标签的内容（插件给了 `retarget` 就软换，没给就重挂，同今天）；位置不动，激活它 | [R2]，见下注 |
| 没有，组里没有预览标签 | 是 | 在目标组开一个新的预览标签，插在活动标签右边，激活 | [R2][R4] |
| 没有 | 否 | 在目标组开一个新的正式标签，插在活动标签右边，激活 | [R4][R9] |

注：VS Code 顶掉预览时是把新的预览插到活动标签右边、同时关掉旧的 [R2]。本仓选**原地换**：同一个实例不拆，插件的 `retarget` 才能软换、保住它的状态（今天的做法，shell.mdx「软换与硬换」）。dockview 的 `addPanel` 不给 `index` 时追加到组末尾 [R28]，所以「插在活动标签右边」要显式给 `index`。

**同一内容在别的组、别的桌面开着，都不算命中**：不跳过去，就在目标组再开一份。要去已开的那份，用切换器（下文）。参考 VS Code `workbench.editor.revealIfOpen` 默认关 [R1]、Obsidian 同一篇笔记可以开在多个标签页 [R12]。

**工具窗格**，查重范围是**当前桌面的所有组**：

| 当前桌面上 | 发生什么 | 参考 |
| --- | --- | --- |
| 有同一定义、同一 key 的实例 | 激活它（在哪一组就在哪一组，不挪） | [R6] |
| 没有 | 按目标组规则开一份，插在活动标签右边，激活 | [R6][R4] |

别的桌面上开着同一个工具窗格，互不相干：每张桌面各有各的一份。参考 VS Code 的多个窗口各开各的工作区，资源管理器这类视图的内容各窗口互不相干（但视图摆在哪个容器，同一配置档的各窗口是共享的）[R6]。工具窗格的 `preview` 与 `placement: 'side'` 照收，语义同文档窗格。

**无论哪一行，打开都不切桌面**。命令带的 `from` 指向别的桌面上的窗格时，开在那张桌面上，当前显示的桌面不变。

**打不开的情况**（照旧）：窗格定义不在注册表里 → 什么都不做，console 与命令回执说明是谁要开什么；`params` 里有外壳保留键 → 摘掉并 warn。

| 步骤 | 发生什么 | 参考 |
| --- | --- | --- |

| 2 | 目标桌面的容器还没挂上（从没切去过）：先在后台把它挂上，不显示 | 本仓容器常驻保活 |

| 6 | 两张桌面各落一次盘 | — |

注：送过去之后跟不跟，参考产品不一致。Chrome「将标签页移至其他窗口」会把标签设成目标窗口的活动标签、并把目标窗口带到前台，也就是跟过去（源码）[R14]；Windows 任务视图「移动到」之后切不切桌面，官方与能访问的二手来源都没写 [R15]。默认不跟（2026-09-19 人拍板），理由是「送走」多半是在整理当前桌面、人还要接着在这儿干活，想跟过去多点一下「切过去」就行。

## 给文档窗格插件的手势约定

外壳看不见插件里面的点击，所以下面这张表是**约定**：各插件照着做，同一个手势在所有插件里意思一样。

| 手势 | 意思 | 插件怎么做 | 参考 |
| --- | --- | --- | --- |
| 单击（在同类文档窗格里） | 本窗格原地换内容 | 自己换，换完 `setPaneContent` | Obsidian 无修饰键 = 在当前标签打开 [R9][R10]；浏览器 |
| 单击（在别的窗格里，比如工具窗格、别的插件） | 预览 | `openPane(…, { preview: true })` | VS Code 在资源管理器里单击 = 预览打开 [R2] |
| Ctrl / ⌘ + 单击，或中键 | 新标签，开在同一组，并切过去 | `openPane(…)`，不要预览、放法缺省 | Obsidian Ctrl / ⌘ = 新标签 [R9]；Chrome Ctrl / ⌘ + 单击与中键 = 新标签 [R13]，见下注 |

## 接口变化

全部是加法；老插件不改一行照跑，但会拿到新的**行为**（查重范围、摆放、不再自动切桌面），见「消费方怎么跟」。

**node 半**

- `registerPane` 的 `PaneSpec` 多一个可选字段 `kind: 'tool' | 'document'`，缺省 `tool`
- `shell.panes` 每条多带 `kind`
- `shell.openPane` 多收 `from?`（来源窗格的实例 id，即 `pane.instance`）与 `placement?`
- 新命令（都经内核事件口转给页面执行，跟 desktop 那几条同一种转发；只读的 `list` 由页面回填）：

| 命令 | 参数 | 干什么 |
| --- | --- | --- |
| `shell.pane.list` | 无 | 所有桌面上开着的窗格：`{ instance, desktop, group, pkg, entryId, paneId, kind, key, title, preview, active }` |
| `shell.pane.focus` | `{ instance }` | 激活它；在别的桌面就切过去（显式切换） |
| `shell.pane.send` | `{ instance, desktop? , newDesktop?, follow? }` | 送到别的桌面，`desktop` 与 `newDesktop` 给一个 |
| `shell.pane.close` | `{ instance }` | 关掉它 |
| `shell.desktop.rename` | `{ id, name }` | 改名 |
| `shell.desktop.delete` | `{ id }` | 删除，上面的窗格一起关掉（不弹确认），回执带关掉了几个；只剩一张时回错 |

`shell.pane.list` 要页面回答，node 半没有容器：页面在每次布局变化时把清单推给 node 半缓存，命令读缓存（已定）。

**浏览器半（`mountPane` 的 args）**

- `shell.openPane(paneId, { key?, params?, preview?, placement? })`：多一个 `placement`；外壳自动把调用它的这个实例当来源
- `shell.setPaneContent({ key, params?, title? })`：新
- `pane.kind`：新，插件知道自己被当成哪一类挂的
- `setPaneTitle` / `keepPane` / `bus` / `portal` / `onVisibility` / `pane.instance` / `pane.params`：不变

**插件探测新能力**：照块笔记那头的做法，按形状判（`typeof shell.setPaneContent === 'function'`），没有就退回今天的行为。老外壳不认 `placement` / `kind`，多带的字段被忽略，不报错。

## 推翻的判据

做完每条落一张轨迹卡（轨迹卡只增不改，旧卡不动）。

| 今天的判据（出处） | 改成 | 为什么 |
| --- | --- | --- |
| 「注册说不出我能开几份」，一个窗格开几份只取决于装着几份不同的内容（shell.mdx） | 注册要说清是工具还是文档 | 说的不是「能开几份」，是「打开这个动作对它是什么意思」：对工具是显示，对文档是装一个内容。两类的查重范围、启动器行为、能不能再开一份都不同，外壳不知道就只能一套规则套两类 |
| 「桌面是分组不是宇宙」：key 全局找份，命中别的桌面就切过去（shell.mdx、轨迹卡 2026-09-12 重构轮） | 本桌优先，只有显式动作切桌面 | 被切走是现状二那种体验的根；参考产品都把这件事做成默认关或可关 [R1][R18][R19] |
| 状态栏「没有『＋一份』那种按钮」，那张表只干「打开，已开就聚焦」（shell.mdx） | 拆成启动器与切换器；启动器对文档窗格就是开一份新的 | 一个列表同时开与切，是现状五的根 [R7] |
| 「预览窗格每容器一份」，全案唯一的桌面特例（shell.mdx） | 每组一个 | 跟 VS Code 一致 [R2]；两列正文各要一个预览标签是正常需求 |
| `placeNext` 按已开份数分三档（shell.mdx） | 目标组规则 | 现状三；新窗格该落在来源旁边、只动一处 [R3][R4] |

shell.mdx 里「第二档相对当前活动窗格」那句与 dockview 源码不符（现状三），改写现状页时一并更正。shell.mdx 引用的「定过的事」「路线」两页在本仓不存在，改写时把判据直接写进现状页与轨迹卡。

## 不做

- **独立窗口**（把一组弹成单独的操作系统窗口）。VS Code、Obsidian 都有 [R8][R11]，dockview 也有 popout 组 [R24]，但它牵扯多窗口之间的协调（本仓至今「多窗口时各页各自执行」），另开一页
- **把标签拖进另一张桌面的某一组、指定落位**。拖到状态栏的桌面上 = 送过去（按目标组规则落位）已在第二轮做了；一路拖进目标桌面、像同一桌面里拖放那样选组选边，要在目标那个 dockview 实例里接住别的实例来的拖放，另开一页
- **快捷键**（切桌面、送到桌面、开到旁边）。候选可参考 Windows 的 Win+Ctrl+←/→ [R16]，但跟插件自己的快捷键怎么分界要单独想，另开一页
- **「已开就跳过去」的设置**（VS Code 的 `revealIfOpen`、macOS 那个开关）。先固定为不跳；真有人要再加
- **桌面排序**、**标签页后台打开**（Chrome 的 Ctrl+单击默认后台 [R13]）：本期不做

## 已拍板（2026-09-19）

人在块笔记仓的会话里看过每条的操作场景对照后选的：

1. **方向四条全要**：两类窗格、本桌优先（只有显式动作切桌面，同一内容只在目标组里查重）、新窗格落在来源旁边（目标组规则）、状态栏拆「新建」与「窗格」两格。上面「推翻的判据」五条随之成立
2. **`kind` 缺省 `tool`**：老插件一个不改就都是工具窗格；文档插件忘了声明，最多少一个「在旁边再开一份」
3. **送过去之后不跟过去**：留在原桌面，状态栏给「切过去」；按住 Shift 选或命令带 `follow: true` 才跟过去
4. **删除桌面时上面的窗格一起关掉**：有窗格先弹确认；命令不弹。（推荐的是「并到当前桌面」，人选了关掉，理由见「桌面」一节的注）

下面三条人没另外表态，按推荐定：

5. **工具窗格每张桌面各一份**，不做「全页一份、在别的桌面打开就拉过来」
6. **预览标签里上报了新内容，外壳不自动转正**，插件自己定（块笔记可以定成「在预览里主动跳转一次就转正」）
7. **`shell.pane.list` 由页面在每次布局变化时推给 node 半缓存**

**第二轮（2026-09-19，人在本仓会话里看过第三期做完的实机状态栏之后定的）**：

8. **「桌面」与「窗格」两格并成一格「桌面」面板**，面板里只摆桌面与各桌面上的窗格，行内的关闭、送到、拉到本桌都拿掉

10. **右键桌面名改名**（双击会跟单击切桌面打架）；**删除一律先确认**，空桌面也确认

下面两条人没另外表态，按推荐定：
